# [30100] Résolveur : clone défaut + move dernière utilisation

- Version : V0
- Milestone : M2
- Statut : draft
- Dépend de : 20100
- Invariants applicables : I1, I2, I4

## Objectif
Décider, pour chaque lecture de variable, sa `Disposition` (`Clone` | `Move`) → `OwnershipMap` (README §4.5). Le clone est le **fallback total** qui compile toujours (I1).

## Périmètre
Analyse de durée de vie locale par `fn` : dernière utilisation d'un binding → `Move` ; usages antérieurs → `Clone`. Itération `for x in coll` → clone des éléments.

## Hors-périmètre
Élision d'emprunt / `Borrow` (→ V1, 30200) ; aliasing mutable explicite `inout`/`ref` (I3, non déclenché en V0).

## Comportement attendu (observable)
- Chaque nœud `Var` (lecture) reçoit `Clone` ou `Move`.
- **Move** ssi **dernière utilisation** dynamique du binding sur **tous** les chemins ; sinon **Clone**.
- Jamais d'auto-clone pour résoudre un partage mutable (I3) — sans objet en V0 (pas d'emprunt).
- Garantie I1/I2 : la sortie compile **toujours** (au pire tout cloné) ; jamais d'`unsafe`.

## Contrat / interface
Produit `OwnershipMap : NodeId→Disposition`. Consomme `Ast`, `TypeMap`.

## Source maps
N/A.

## Critères d'acceptation
- Tout `Var` lu a une `Disposition`.
- Binding utilisé 1× en fin de portée → `Move` ; utilisé 2× → 1ᵉʳ `Clone`, dernier `Move`.
- Programme V0 entièrement « clonable » compile (fallback I1).

## Risques / questions ouvertes
- ❓ « dernière utilisation » à travers `if`/`while`/`for` : une utilisation **dans** une boucle n'est jamais une « dernière » sûre → `Clone`. Règle conservatrice à figer.
