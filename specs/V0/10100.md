# [10100] Lexer indentation-sensitive

- Version : V0
- Milestone : M0
- Statut : draft
- Dépend de : —
- Invariants applicables : I9, I14

## Objectif
Transformer les octets d'un fichier `.irn` en `Vec<Token>` (README §4.1), en gérant l'off-side rule (Python) **et** la suspension d'indentation dans les régions accolades (README §1bis).

## Périmètre
Tokenisation : littéraux (`int float bool str`), identifiants, mots-clés (§4.1), opérateurs/ponctuation (§4.1), synthétiques `Indent`/`Dedent`/`Newline`. `Span` octets (§3). Erreurs lexicales (tab en indentation, caractère illégal, littéral mal formé).

## Hors-périmètre
Grammaire/structure (→ 10200). Désambiguïsation `{}` bloc vs dict (→ 10200 ; le lexer émet juste `{`/`}`). Types (→ 20100).

## Comportement attendu (observable)
- Émet un flux de `Token` portant chacun un `Span` octet exact.
- **Off-side** : hors accolades, pile d'indentation ; émet `Indent`/`Dedent` aux changements de niveau, `Newline` en fin de ligne logique. Indentation = **espaces** ; tabulation/mélange = **erreur lexicale**.
- **Accolades** : suit la profondeur `{`…`}` ; à profondeur > 0, **suspend** `Indent`/`Dedent` ; `Newline` reste émis comme séparateur.
- Déterminisme : mêmes octets → même flux.

## Contrat / interface
Produit `Vec<Token>` conforme à README §4.1. Consomme : source `.irn` (+ `FileId`).

## Source maps
N/A pour le mapping Rust (c'est le lowering). **Garantit** la justesse des `Span` octets sur lesquels tout I8 s'appuie.

## Critères d'acceptation
- Le programme V0 (§6) se tokenise dans **les deux syntaxes** de bloc.
- Indentation tab/mélange → erreur lexicale au bon `Span`.
- `Span` octets exacts : re-slicer la source par `Span` redonne le lexème.
- Un bloc `{ … }` multi-lignes non indenté tokenise **sans** `Indent`/`Dedent`.
