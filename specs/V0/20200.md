# [20200] Inférence Option/Result depuis le flux

- Version : V0
- Milestone : M1
- Statut : draft
- Dépend de : 20100
- Invariants applicables : I6, I11, I12, I13

## Objectif
Compléter le `TypeMap` : déduire `Option<T>` / `Result<T, IronError>` par analyse de flux (I11), unifier l'erreur en `IronError` (I13), garder `NaN` en `f64` (I12).

## Périmètre
Analyse de flux des `fn` : présence/absence de valeur de retour → `Option` ; usage de `?` / opération faillible → `Result`. Propagation par `?`.

## Hors-périmètre
Consommation terminale par `match` (→ V3). Inférence d'un `E` précis (→ post-1.0, I13).

## Comportement attendu (observable)
- Une `fn` dont **un chemin renvoie `T` et un autre n'en renvoie pas** (bare `return` / chute) → `Option<T>` ; chemins-valeur → `Some`, autres → `None` (I11).
- Une `fn` utilisant `?` ou une op faillible → `Result<T, IronError>` (I13).
- `?` propage `None`/`Err` vers l'appelant (dont le type doit être cohérent, sinon erreur remontée).
- `NaN` reste `F64`, **ne déclenche pas** d'`Option` (I12).

## Contrat / interface
Étend `TypeMap`. Consomme `Ast`, `TypeMap` (20100).

## Source maps
N/A. Les incohérences de propagation `?` pointent un `Span`.

## Critères d'acceptation
- `fn` à chemin sans valeur → `Option<T>` ; `fn` avec `?` → `Result<T, IronError>`.
- `NaN` typé `F64`.
- `?` sur appelant incompatible → erreur au `Span`.

→ phase 2 (`planification/`).
