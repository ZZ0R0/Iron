# [40100] Lowering AST → TokenStream (core)

- Version : V0
- Milestone : M2
- Statut : draft
- Dépend de : 20200, 30100
- Invariants applicables : I9, I10

## Objectif
Produire le Rust sous forme de `proc_macro2::TokenStream` (I10, **jamais de chaînes**) à partir de `Ast` + `TypeMap` + `OwnershipMap`, **plus** la `SourceMap` (marqueurs liés au `NodeId`).

## Périmètre
Lowering de tout le sous-ensemble V0 vers Rust idiomatique : items, contrôle de flux (`if/while/for/break/continue`), exprs, collections (`Vec`/`HashMap`), `Option`/`Result` + `?`, dispositions clone/move. Émission du crate : `#![forbid(unsafe_code)]` + type `IronError` (§4.8).

## Hors-périmètre
Pretty-print (→ `prettyplease`, appelé par 70100) ; ré-localisation post-format (→ 60100).

## Comportement attendu (observable)
- `Ast` → `TokenStream` Rust **compilable**, en appliquant `OwnershipMap` (`Clone`→`.clone()`, `Move`→déplacement naturel) et `TypeMap`.
- `for x in coll` → boucle Rust clonant l'élément ; `list`/`dict` → `Vec`/`HashMap` ; `?` → `?` Rust.
- Émet, par **instruction** (cible : expression, §4.6), un marqueur reliant le Rust généré au `NodeId`/`Span` Iron → `SourceMap`.
- Aucun `unsafe` ; `#![forbid(unsafe_code)]` en tête.

## Contrat / interface
Produit `(TokenStream, SourceMap)`. Consomme `Ast`, `TypeMap`, `OwnershipMap`.

## Source maps
**Producteur** de la `SourceMap` (§4.6). Décision clé : marqueurs **survivant à `prettyplease`** (dérisquage n°1, coordonné avec 60100).

## Critères d'acceptation
- Programme V0 → `TokenStream` que `cargo` compile (via 70100).
- Sémantique préservée (exécution = attendu).
- `SourceMap` non vide, alignée sur les `NodeId`.

## Risques / questions ouvertes
- 🔶 **Mécanisme de marqueurs** survivant au reformatage : le point dur. Prototyper en squelette (granularité instruction) avant l'expression.
- ❓ stratégie `Move` exacte en Rust (move naturel vs annotations) — figer en planif.
