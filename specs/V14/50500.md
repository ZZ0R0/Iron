# [50500] Portée connue du moteur & rapport de génération (zéro drop silencieux)

- Version : V14
- Milestone : binding-système
- Statut : draft
- Dépend de : [50300] (auto-gen rustdoc), [50400] (deux couches)
- Invariants applicables : I8, I7, I6

## Objectif
Rendre le moteur **conscient de sa propre portée** et le forcer à **dire ce qu'il ne sait pas binder, à la
génération**. Aujourd'hui, quand le moteur ne sait pas projeter un item, il **abandonne en silence**
(`project()` → `None`, ctor sauté, générique non-béni droppé, alias non-expansé). Conséquence : l'utilisateur
découvre le trou **plus tard**, à la compilation de **son** programme Iron, avec un message qui parle d'un
identifiant manquant — **sans** savoir que le **binding** était incomplet ni **quoi** écrire à la main. V14
inverse ça : chaque abandon devient un **diagnostic structuré** (I8), agrégé en un **rapport de génération**
qui dit, **avant** toute compilation utilisateur, *ce qui n'a pas été lié, pourquoi, et quoi écrire*. C'est
l'exigence centrale : **« si le moteur SAIT qu'il ne peut pas résoudre, il doit en informer l'utilisateur ».**

## Périmètre
- La **taxonomie fermée** des raisons de non-binding (`SkipReason`).
- Le **diagnostic structuré** par item sauté (`SkipDiagnostic`).
- Le **rapport** de génération (fichier + résumé stderr) et la **couverture calculée**.
- L'**invariant de complétude** : `seen_public == bound + skipped` (zéro silencieux).

## Hors-périmètre
- Les **règles** qui *réduisent* le nombre de skips (C1–C4) → [50600].
- La composition gen/curé → [50400].

## Comportement attendu

**Chaque abandon = un `SkipDiagnostic`.** Là où le moteur retourne aujourd'hui `None`/drop, il produit :
```
SkipDiagnostic {
    rust_path: String,        // "aes_gcm::AesGcm::encrypt"
    item_kind: ItemKind,      // Fn | Method | Ctor | Type | Field | Variant
    reason:    SkipReason,    // cf. taxonomie ci-dessous
    hint:      String,        // action : "écris dans <crate>.iri : extern type ... { method encrypt(...) = \"...\" }"
}
```

**Taxonomie `SkipReason` — FERMÉE et exhaustive** (toute nouvelle cause d'abandon DOIT s'y ajouter — c'est
le contrat qui garantit qu'aucun abandon n'échappe au rapport) :

| Variante | Sens | Famille typique |
|---|---|---|
| `UnmappedType(rust_type)` | type de param/retour sans projection Iron | types composés exotiques |
| `GenericTraitMethod(trait)` | signature dépend d'une borne de trait non-bénie/non-projetée | AEAD `encrypt`/`decrypt` |
| `ConstGenericShape` | item dépend d'une valeur-au-niveau-type (`Const<N>`, typenum) | `Vector3::new` (dimensions) |
| `UnexpandableAlias(alias)` | alias dont la cible n'a pu être résolue | alias inter-crate non documenté |
| `BorrowedReturnNonIdiom(rust_type)` | retour emprunté hors idiome connu (ni Display, ni clone) | zéro-copie tenu (`Smf<'a>`) |
| `StreamBuilderApi` | API builder/flux non réductible à une fn one-shot | flate2 `Encoder` |
| `MacroOrHidden` | item absent du rustdoc (macro, `#[doc(hidden)]`) | grammaires `pest` |
| `ReexportSourceUndocumented(crate)` | façade dont le crate-source n'a pu être documenté | re-export profond |
| `OrphanCuration` | entrée **curée** sans homologue auto (possible drift de version, cf. [50400]) | binding curé obsolète |

**Le rapport.** `ironc add <crate>` écrit, à côté de `<crate>.gen.iri`, un **`<crate>.iri.report.md`** lisible
humain, **et** un **résumé stderr** :
```
binding `aes-gcm` : 41 items publics — 33 liés, 8 sautés (couverture 80,5 %)
  SAUTÉS :
  · aes_gcm::AesGcm::encrypt   [GenericTraitMethod: aead::Aead]
      → écris dans aes-gcm.iri :  extern type Aes256Gcm { method encrypt(nonce: list[u8], pt: list[u8]) -> Result[list[u8]] = "..." }
  · aes_gcm::AesGcm::decrypt   [GenericTraitMethod: aead::Aead]   → ...
  ...
```
- La **couverture** (les fameux « 62–92 % ») devient un **nombre calculé** : `bound / seen_public`.
- Le rapport est un **diagnostic I8** : il **oriente vers l'action** (le `hint` est un squelette d'entrée
  `.iri` à compléter), exactement comme un message d'erreur source-mappé oriente vers la ligne fautive.
- **Code de sortie** : `0` même s'il y a des skips (un skip est une **information**, pas une erreur). Option
  **`--strict`** → échec si couverture < seuil (utile en CI quand on **vise** zéro binding manuel).

**Invariant de complétude (le cœur de « le moteur connaît sa portée »).** Le moteur compte les items publics
vus (`seen_public`) et asserte en fin de génération :
```
seen_public == bound + skipped
```
**Aucun item public ne peut disparaître sans apparaître soit comme lié, soit comme sauté avec une raison.**
C'est ce qui transforme « le binder droppe en silence » en « le binder **sait** et **dit** ».

## Contrat / interface
- **Refactor de fondation** : `project()` et les collecteurs (ctors, méthodes, champs, alias) passent de
  `Option<Sig>` à **`Result<Sig, SkipDiagnostic>`** — le `None` actuel devient une **raison nommée**. C'est
  la **vague 1 de V15** (fondation, avant tout fan-out de capacités).
- **Sortie** : `<crate>.gen.iri` + `<crate>.iri.report.md` + résumé stderr + couverture (`f`) + code de sortie.
- **API interne stable** : `SkipReason` (enum fermé), `SkipDiagnostic` (struct), `Coverage { seen, bound, skipped }`.

## Source maps
**Satisfait I8 par le rapport lui-même.** Le mapping pertinent ici n'est pas `.irn`↔Rust mais **item Rust ↔
raison ↔ action** : le rapport EST cette table. Toute évolution du moteur (50600) doit **mettre à jour** la
couverture et la liste des sautés — la frontière reste **machine-connue**, jamais re-devenue prose.

## Critères d'acceptation
- Sur **aes-gcm**, le rapport liste `encrypt`/`decrypt` en `GenericTraitMethod` **avant** toute compilation
  d'un programme utilisateur, avec un `hint` exploitable.
- **Zéro drop silencieux** : test automatisé sur ≥3 crates (ex. aes-gcm, nalgebra, flate2) vérifiant
  `seen_public == bound + skipped`.
- La **couverture** est un nombre affiché et reproductible.
- `--strict` fait échouer `ironc add` si couverture < seuil ; sans `--strict`, code de sortie `0` malgré skips.
- Une entrée **curée orpheline** (sans homologue auto) est signalée `OrphanCuration` (lien avec [50400]).

## Décomposition
→ **V15, vague 1** (fondation, avec [50400]) : `Result<Sig, SkipDiagnostic>`, taxonomie, rapport, invariant
`seen==bound+skipped`. Unités `planify-1.x` (planif V15).

## Risques / questions ouvertes
- **🔶 Sur-signalement** : le moteur peut classer `UnmappedType` un item qu'une règle future (50600) saurait
  lier. **Acceptable et voulu** : sur-signaler > droper en silence ; la couverture **monte** quand C1–C4
  arrivent, et le rapport le **montre**.
- **❓ Granularité de la taxonomie** : 9 variantes. Trop fin = bruit, trop grossier = `hint` inutile. On fige
  ces 9 ; on **fusionne/scinde** au vu du rapport réel (décision de réalisation, pas de cadrage).
- **❓ Seuil `--strict`** : valeur par défaut (ex. 90 %) — décision UX, différée.
