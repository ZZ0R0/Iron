# [30800] Le moteur d'ownership unifié — borrow/move/clone whole-program à point fixe

- Version : V17
- Milestone : ownership-engine
- Statut : draft
- Dépend de : [30500] (escape interprocédurale, V16 — 1ᵉʳ pilier), I15 (moteur de types — modèle de référence)
- Invariants applicables : I1, I2, I3, I4, I15

## Objectif
Une **seule** analyse de flot whole-program qui décide, pour **chaque** site d'usage d'une valeur non-`Copy`,
si c'est un **emprunt**, un **move** ou un **clone** — et produit **une** structure (`OwnershipPlan`) consommée
uniformément par le lowering ([40500]). Remplace les **deux** analyses hétérogènes de `resolve.rs` (escape →
`ParamModes` ; `compute_moves` → `OwnershipMap` single-use) par **un** moteur cohérent, jumeau de l'inférence
de types. C'est le **socle** qui rend stables et cohérentes toutes les features de surface qui exposent
aujourd'hui les fuites de cette couche (opérateurs, méthodes, `for`, captures).

## Périmètre
- Le **modèle unique** borrow/move/clone et son **treillis monotone**.
- Le **graphe de flot/d'appels unique** (fns libres + méthodes + externes).
- Le **point fixe** (modes de params interprocéduraux + dispositions par site).
- La **taxonomie des sites d'usage** (où une valeur est lue/déplacée/consommée).
- La **sortie figée `OwnershipPlan`** (le contrat consommé par [40500]).

## Hors-périmètre
- **Borrow-checking complet** : `rustc` reste le filet (I2). Le moteur **choisit** emprunt/move/clone, il ne
  prouve pas l'absence d'aliasing mutable.
- **Durées de vie essentielles** (référence stockée qui survit) → clone / `rust{}` (0.1 %).
- **Partage mutable** : `inout`/`shared` explicite (I3), inchangé.

## Comportement attendu

### Le modèle (une seule question, partout)
Pour un usage d'une valeur `v` (non-`Copy`) au site `s` :
```
Borrow     si v est seulement LUE en s, OU prêtée à une position empruntante (callee ByRef, base de champ/index,
           récepteur de méthode, comparaison, print/len, itérable de for, opérande d'opérateur lu).
BorrowMut  si v est mutée en place via une position &mut (inout, méthode mutante, opérateur composé).
Move       si s est la DERNIÈRE-UTILISATION prouvée de v ET qu'un ownership est requis (retour, stockage,
           passage à une position ByValue, capture move).
Clone      sinon : v est réutilisée APRÈS une consommation, OU s'échappe sans être le dernier usage, OU
           **incertitude** (sur-approximation sûre).
```

### Le treillis (monotone → terminaison)
- **Modes de params** : `ByRef` (optimiste) ⊒ `ByRefMut` ⊒ `ByValue`. Rétrogradation seulement.
- **Dispositions par site** : `Borrow` ⊒ `Move` ⊒ `Clone`. Rétrogradation seulement.
- **Init optimiste** ; on ne fait que **descendre** dans le treillis sur preuve d'un besoin plus fort. Monotone
  ⇒ **point fixe terminant** (même en récursion mutuelle).

### Le graphe de flot/d'appels (unique, partagé)
Construit **une fois** : arêtes d'appel (fn libre par nom ; méthode `x.m` résolue via `TypeMap` → `Type::m` ;
externe → modes des bindings `recv`/`param_owned`) ; flot intra-fonction (lectures, dernière-utilisation,
ordre d'évaluation **intra-expression** — ce que le single-use actuel rate). Consommé **aussi** par
l'inférence de propagation ([21800], si réactivée) — une seule construction.

### La taxonomie des sites d'usage (exhaustive)
Argument d'appel · récepteur de méthode · **opérande d'opérateur** · variable de boucle `for` · valeur de
retour · champ de struct-literal / élément de collection · capture de closure/thread · RHS d'affectation ·
scrutateur de `match`. **Chaque** site reçoit une `Disp` du moteur — fini les règles par-construct.

### `OwnershipPlan` (la sortie figée)
```rust
pub enum Disp { Borrow, BorrowMut, Move, Clone }
pub enum ParamMode { ByRef, ByRefMut, ByValue }   // (existant, étendu)
pub struct OwnershipPlan {
    pub sites: HashMap<NodeId, Disp>,                  // disposition par site d'usage
    pub params: HashMap<String, Vec<ParamMode>>,       // modes par (fn/méthode `Type::m`, param) — subsume ParamModes
}
```
> **Décision figée** : `OwnershipPlan` est la **seule** sortie ownership. `resolve.rs` (les deux analyses
> actuelles) y est **refondu**. `lower` ne lit **que** ce plan ([40500]).

### Exemples `Iron → Rust`
- `for obj in objs { obj.hit(r) }` — `obj` lu-seul → `Borrow` (`for obj in objs.iter()`) ; `r` à une position
  `ByRef` de `hit` → `Borrow` (`obj.hit(r)`, pas `r.clone()`). *(Méthodes + for-élément, gratuits car dans le moteur.)*
- `return v.sub(n.scale(2.0 * v.dot(n)))` — `n` réutilisé intra-expression → 1ʳᵉ lecture `Borrow`, dernière
  `Move`/`Borrow` ; **jamais** `Clone` forcé → plus de `.copy()`.
- `c = a + b` (Vec3 empruntés) — opérandes lus → `Borrow` via le plan (un seul chemin, comme une méthode) → compile.

## Contrat / interface
- **Entrée** : AST + `TypeMap` (le moteur tourne **après** l'inférence — I9 — pour résoudre les méthodes).
- **Sortie** : `OwnershipPlan` (remplace `(OwnershipMap, ParamModes)`). Changement de signature de `resolve` →
  `driver.rs` et `lower.rs` adaptés (borné, mécanique).
- **Sûreté figée** : sur-approximation conservatrice ; dans le doute, `Clone`/`ByValue`. Jamais d'emprunt non prouvé sûr.

## Critères d'acceptation
- **Phase de migration** : à l'étape (a) (le moteur reproduit l'existant), **corpus 80 + raytracer
  bit-à-bit inchangés** (zéro diff du Rust généré). C'est la preuve que le socle est neutre avant de l'exploiter.
- **Après greffe** : ray tracer sans `r.clone()`/`rec.clone()` résiduels ; `a+b` sur valeur empruntée compile ;
  `.copy()` manuel inutile. Perf ≥ V16 (mesurée).
- Le point fixe **termine** (récursion mutuelle). 0 `unsafe`. Corpus 80 vert à chaque étape.

## Décomposition

## Risques / questions ouvertes
- **🔴 Rayon de souffle maximal** : c'est la couche qui détermine la structure d'emprunts de **tout** le Rust
  généré. Mitigation : l'étape (a) **neutre** (reproduit l'existant) avant toute exploitation ; corpus-gate.
- **❓ Dernière-utilisation intra-expression** : exige l'ordre d'évaluation (Rust : gauche-à-droite des args).
  À spécifier précisément en planif.
- **❓ Unification avec le moteur de types** : un seul graphe partagé serait idéal mais les deux tournent à des
  étapes différentes (I9) ; option = chaque passe construit le sien (bon marché) — à trancher en planif.
