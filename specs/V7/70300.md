# [70300] Manifeste `ironc.toml`

- Version : V7 · Milestone : M4 · Statut : draft · Dépend de : 70100 · Invariants : I9

## Objectif
Un **manifeste de projet** `ironc.toml` — métadonnées, dépendances, point d'entrée — pour passer du
fichier isolé au **projet**. C'est le contrat tooling ↔ deps ↔ bind (D4).

## Périmètre
- Schéma TOML (D4) : `[package] name/version/edition` ; `[dependencies] crate = "x.y"` ; `[iron] entry`.
- `ironc build/run` détectent `ironc.toml` (sinon mode fichier seul, rétro-compat).

## Hors-périmètre
- Workspaces multi-paquets ; features ; profils de build (V8).

## Comportement attendu
- `ironc.toml` :
  ```toml
  [package]
  name = "demo"; version = "0.1.0"; edition = "2021"
  [dependencies]
  serde_json = "1"
  [iron]
  entry = "src/main.irn"
  ```
  → `Cargo.toml` généré avec `[package]` + `[dependencies] serde_json = "1"` ; compile `entry`.

## Contrat / interface (D4)
`driver` : si `ironc.toml` présent, le parser (crate `toml` ou parse minimal) → `Manifest{ package, deps,
entry }`. `[dependencies]` → `crates` passés à `emit_project`. Sans manifeste → comportement actuel.

## Critères d'acceptation
- Un projet avec `ironc.toml` + dep → `Cargo.toml` correct + build vert ; `entry` respecté.
- Absence de `ironc.toml` → mode fichier isolé inchangé (corpus 37/37).
