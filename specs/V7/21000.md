# [21000] Variantes d'enum à champs nommés

- Version : V7 · Milestone : M2 · Statut : draft · Dépend de : 20300, 20600 · Invariants : I6, I9

## Objectif
Compléter les enums (différé V6/20600) : variantes à **champs nommés** (struct-variants Rust), pour des
données de variante lisibles au-delà du tuple positionnel.

## Périmètre
- Déclaration `enum E: V(a: i64, b: str)` (champs nommés) en plus de la forme tuple `V(i64, str)`.
- Construction `E.V(a=1, b="x")` ; motif `E.V(a, b)` (positionnel par nom) et `E.V(a=pa, b=pb)`.

## Hors-périmètre
- Variantes mixtes ; valeurs par défaut de champ (V8).

## Comportement attendu
- `enum Shape: Circle(r: f64)  Rect(w: f64, h: f64)` → `enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 } }`.
- `Shape.Rect(w=3.0, h=4.0)` → `Shape::Rect { w: 3.0, h: 4.0 }`.
- `match s: Shape.Rect(w, h): …` → `Shape::Rect { w, h } => …`.

## Contrat / interface
IR : variantes d'enum portent des **champs nommés optionnels** (`Vec<(String, Type)>` au lieu de
`Vec<Type>` seul) — extension de fondation D0. `infer` : `variant_field_types` par nom. `lower` :
struct-variant `V { … }` + motifs `V { a, b }`. Rétro-compat : variante tuple inchangée.

## Source maps
N/A (exhaustivité/typage → remontée `rustc`, I8).

## Critères d'acceptation
- `Shape.Rect(w=3.0, h=4.0)` construit + `match` extrait w/h → aire 12.0.
- Variantes tuple **et** nommées coexistent ; corpus inchangé (enum_match).

## Décomposition
→ planif : IR (champs nommés), parser (decl + construction + motif), infer, lower.

## Risques / questions ouvertes
- ✅ Liaison : positionnelle par nom `V(a, b)` **et** explicite `V(a=pa)` (le ❓ V6 tranché : les deux).
