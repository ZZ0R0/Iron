# [70500] `ironc test` — runner de tests

- Version : V7 · Milestone : M5 · Statut : draft · Dépend de : 70300, 10800 · Invariants : I9

## Objectif
Un **runner de tests** Iron : fonctions de test + assertions → exécutées via `cargo test`. Aujourd'hui rien
(seuls les tests Rust du compilateur existent).

## Périmètre
- `test fn nom(): assert …` (fns marquées `test`) ; `ironc test` les compile en `#[test]` Rust + lance `cargo test`.
- `assert` (10800) + `assert_eq(a, b)` ; rapport pass/fail remonté.

## Hors-périmètre
- Fixtures/mocks ; tests paramétrés ; bench (V8).

## Comportement attendu
- `test fn addition(): assert_eq(2 + 2, 4)` → `#[test] fn addition() { assert_eq!(2 + 2, 4); }`.
- `ironc test` → compile le crate en mode test + `cargo test` ; échec d'assert → remonté au `Span` Iron (I8).

## Contrat / interface
Parser : modificateur `test` sur `fn` → `Item` marqué test. `lower` : émet `#[test]`. `driver` : sous-commande
`test` → `cargo test` dans le projet généré ; parse la sortie cargo → rapport.

## Source maps
Échec d'assertion → `Span` Iron via la remontée existante (I8).

## Critères d'acceptation
- Un fichier avec 2 `test fn` (un pass, un fail) → `ironc test` rapporte 1 pass / 1 fail au bon `Span`.
- `test fn` non émise dans un build normal (`build`/`run`) ; corpus inchangé.

## Décomposition
→ planif : parser `test fn`, lower `#[test]`, sous-commande `cargo test` + rapport.

## Risques / questions ouvertes
- 🔶 `test` comme mot-clé contextuel (ne pas casser un identifiant `test`) — soft-keyword en tête de `fn`.
