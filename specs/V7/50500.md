# [50500] `bind` complet : str / collections / structs / sous-modules

- Version : V7 · Milestone : M4 · Statut : draft · Dépend de : 50200, 50400 · Invariants : I2, I6, I7

## Objectif
Lever la dette de `bind` (différé V6/50400) : aujourd'hui `ironc bind` ne mappe que `i64/f64/bool`. Pour
binder des crates réelles, couvrir `str`/`String`, collections, structs publics, et les **chemins en
sous-module**.

## Périmètre
- `bind::map_type` étendu : `str`/`String`→`str`, `Vec<T>`→`list[T]`, `HashMap`→`dict`, `Option`/`Result`,
  structs publics → `Type::Struct`/`Extern`.
- Résolution de **chemin** via `.paths` rustdoc-json (`crate::module::fn` exact).
- Items non mappables (génériques complexes, traits) **sautés et comptés** (dégradation propre, D5).

## Hors-périmètre
- Génériques dans les bindings ; macros ; lifetimes explicites (V8).

## Comportement attendu
- `pub fn greet(name: &str) -> String` → `extern fn greet(name: str) -> str` ; chemin `mycrate::greet`.
- `pub fn parse(s: &str) -> Vec<i64>` → `… -> list[i64]`.
- Rapport `bind` : « N items bindés, M sautés (raison) ».

## Contrat / interface
`bind.rs` : `map_type` couvre les familles ci-dessus ; lecture de `.index`/`.paths` rustdoc-json ;
tolérance multi-versions (≥ v57, dégrade si champ absent). Sortie `.iri` au format existant (50200).

## Source maps
N/A (`bind` est hors pipeline de compilation).

## Critères d'acceptation
- `bind` d'une crate à API `&str`/`Vec`/struct → `.iri` **utilisable** (compile à l'usage).
- Items non mappables comptés dans le rapport ; aucun `.iri` invalide produit.

## Décomposition
→ planif : `map_type` (str/collections/struct), résolution chemin, comptage/rapport.

## Risques / questions ouvertes
- 🔶 Format rustdoc-json **instable** entre versions (D5) — cibler une version, dégrader proprement, tester.
- 🔶 `&str` vs `String` en signature → tous deux `str` côté Iron (la lower réinjecte `.to_string()`/`&`).
