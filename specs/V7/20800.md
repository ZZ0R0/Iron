# [20800] Types numériques élargis (zoo Rust complet)

- Version : V7 · Milestone : M2 · Statut : draft · Dépend de : 20100 · Invariants : I2, I6, I12

## Objectif
Exposer **tout** le zoo numérique Rust (décision D1) pour l'interop bas niveau et la FFI : aujourd'hui
seuls `i64`/`f64` existent, ce qui bloque les APIs typées `u32`/`usize`/`char`.

## Périmètre
- Types par **annotation** : `i8 i16 i32 i64 i128 isize`, `u8 u16 u32 u64 u128 usize`, `f32 f64`, `char`.
- Littéraux **inchangés** : entier → `i64`, flottant → `f64` par défaut (rétro-compat).
- Conversions explicites `to_u32(x)` / `as` (cast). `char` ↔ littéral `'a'`.

## Hors-périmètre
- Inférence numérique globale (reste best-effort + défaut `i64`/`f64`) ; arithmétique saturée/checked explicite (V8).

## Comportement attendu
- `n: u32 = 5` → `let n: u32 = 5u32;` ; `i: usize = len(xs)` → `usize`.
- `c: char = 'a'` → `let c: char = 'a';`.
- Overflow = défaut `rustc` (panic debug / wrap release) — I2, pas de coût Iron.
- `to_u32(x)` → `(x as u32)` ; cast borné par `rustc`.

## Contrat / interface
`parse_type` reconnaît tout le zoo → `Type::Num(NumKind)` (élargit `I64`/`F64`) ou variantes dédiées.
`lower_type` mappe 1-1. Littéraux annotés → suffixe concret. `is_copy` : tous numériques + `char` = Copy.
`infer` : annotation prime ; sinon défaut `i64`/`f64`.

## Source maps
N/A (conflit de type numérique → remontée `rustc` au `Span` Iron, I8).

## Critères d'acceptation
- `n: u32 = 5`, `i: usize`, `c: char = 'z'` compilent + s'exécutent.
- Passage d'un `u32`/`char` à une fn Rust bindée typée (interop) compile ; corpus inchangé (défauts `i64`/`f64`).

## Décomposition
→ planif : IR (NumKind, vague 1), parser (types + `char`), lower_type, casts.

## Risques / questions ouvertes
- 🔶 Ambiguïté `{integer}`/`{float}` si annotation incomplète → suffixer le littéral à la cible (déjà fait i64/f64).
- 🔶 Représentation IR : `Type::Num(NumKind)` (compact) vs N variantes — figer en fondation D0.
