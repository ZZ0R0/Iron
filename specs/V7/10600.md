# [10600] Compréhensions liste / dict / set

- Version : V7 · Milestone : M2 · Statut : draft · Dépend de : 10400, 20800, 20900, 20700 · Invariants : I1, I6, I9

## Objectif
Compréhensions à la Python — construction concise de collections — aujourd'hui impossibles (boucle + `push`).

## Périmètre
- Liste `[f(x) for x in xs if p(x)]` ; dict `{k(x): v(x) for x in xs}` ; set `{f(x) for x in xs}` ;
  filtre `if` optionnel ; un seul `for` (mono-niveau).

## Hors-périmètre
- `for` imbriqués multiples ; compréhensions de générateur (lazy, V8).

## Comportement attendu
- `[x * x for x in xs]` → `xs.into_iter().map(|x| x * x).collect::<Vec<_>>()`.
- `[x for x in xs if x > 0]` → `xs.into_iter().filter(|x| *x > 0).map(|x| x).collect::<Vec<_>>()`.
- `{x: x*x for x in xs}` → `xs.into_iter().map(|x| (x, x*x)).collect::<HashMap<_,_>>()`.
- `{x % 3 for x in xs}` → `…collect::<HashSet<_>>()`.

## Contrat / interface
IR (fondation D0) : `ExprKind::Comp { kind: List|Dict|Set, body, var: Pattern, iter, cond: Option<Expr> }`.
`infer` : type de collection depuis `body`/`iter`. `lower` : chaîne d'itérateurs (filter/map/collect),
réutilise la machinerie closures (20700). Le `if` filtre sur copie de l'élément (robuste).

## Source maps
Marqueur sur l'instruction contenant la compréhension.

## Critères d'acceptation
- `[x*x for x in [1,2,3]]` → `[1,4,9]` ; `[x for x in range(5) if x % 2 == 0]` → `[0,2,4]`.
- Dict/set compréhension compilent + s'exécutent ; corpus inchangé.

## Décomposition
→ planif : IR (vague 1), parser (syntaxe `for…in…if`), infer, lower (itérateurs).

## Risques / questions ouvertes
- 🔶 Désambiguïsation `[… for …]` vs liste littérale — le mot-clé `for` après la 1ʳᵉ expression.
- 🔶 Set vs dict en `{…}` : présence de `:` ⇒ dict, sinon set.
