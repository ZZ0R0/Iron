# [60200] Source maps — granularité expression

- Version : V7 · Milestone : M7 · Statut : draft · Dépend de : 60100, 40100 · Invariants : I8, I2

## Objectif
Atteindre la cible d'I8 (différé V6) : mapping `Span` Iron ↔ Rust à la granularité **expression**
(aujourd'hui = instruction), pour pointer le **sous-bout** fautif d'une erreur `rustc`.

## Périmètre
- Marqueur par **expression** survivant à `prettyplease`, sans polluer le binaire ni casser la robustesse.
- Remontée d'une erreur `rustc` au sous-bout (opérande), pas juste la ligne.

## Hors-périmètre
- Débogueur pas-à-pas ; DWARF.

## Comportement attendu
- Erreur sur `a + b` dans `x = f(a) + g(b)` → pointe `a + b` (ou l'opérande), pas la ligne entière.

## Contrat / interface
`lower` : marqueurs niveau `Expr` via mécanisme **« invisible »** (à l'étude : `#[doc]`/span-only, ou table
d'offsets sans token émis) — **ne pas** régresser la survie au reformatage (dé-risque n°1). `sourcemap` :
ré-localisation fine post-format. Maîtriser la densité (retirer du binaire final).

## Source maps
**C'est** la spec source-maps (raffinement de 60100).

## Critères d'acceptation
- Une erreur `rustc` forcée sur une sous-expression → message pointant le **sous-bout** Iron.
- Robustesse au reformatage **conservée** (les tests source-map instruction passent toujours).

## Décomposition
→ planif : choix du mécanisme « invisible », émission marqueurs expr, ré-localisation, tests robustesse.

## Risques / questions ouvertes
- 🔶 **Risque majeur** (déjà flagué V6) : trop de marqueurs ⇒ `prettyplease` les déplace/fusionne. Le
  mécanisme « invisible » doit être validé sur un prototype **avant** déploiement large.
