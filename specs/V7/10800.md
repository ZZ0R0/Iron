# [10800] Ternaire, `in`/`not in`, `assert`, slicing

- Version : V7 · Milestone : M1 · Statut : draft · Dépend de : 10200, 80500 · Invariants : I1, I6, I9, I8

## Objectif
Quatre constructions d'expression/instruction courantes et absentes : ternaire, appartenance `in`,
`assert`, et slicing de listes/chaînes.

## Périmètre
- Ternaire `a if cond else b` ; `x in coll` / `x not in coll` ; `assert cond` (+ message optionnel) ;
  slicing `xs[a:b]`, `xs[a:]`, `xs[:b]`.

## Hors-périmètre
- Slicing à pas `xs[a:b:step]` (V8) ; `assert` désactivable (mode release).

## Comportement attendu
- `m = a if a > b else b` → `let m = if a > b { a } else { b };`.
- `x in xs` (liste) → `xs.contains(&x)` ; `k in d` (dict) → `d.contains_key(&k)` ; `not in` → négation.
- `assert n > 0` → `assert!(n > 0);` ; `assert n > 0, "msg"` → `assert!(n > 0, "msg");`.
- `xs[1:3]` → `xs[1..3].to_vec()` ; `s[1:3]` (str) → `s[1..3].to_string()`.

## Contrat / interface
IR (fondation D0) : `ExprKind::{Ternary{cond,then,els}, Slice{base,lo,hi}}`, `BinOp::{In, NotIn}`,
`StmtKind::Assert{cond, msg}`. `infer` : ternaire = type des branches ; `in` → Bool ; slice → type de base.
`lower` : `if/else` expression, `contains`/`contains_key`, `assert!`, `[a..b].to_vec()`.

## Source maps
`assert` échoué porte le `Span` Iron (I8) — marqueur sur l'instruction.

## Critères d'acceptation
- `a if a>b else b` (a=3,b=7) → 7 ; `3 in [1,2,3]` → true ; `assert 1==1` passe ; `[10,20,30][0:2]` → `[10,20]`.
- `not in`, slice de chaîne, assert avec message compilent ; corpus inchangé.

## Décomposition
→ planif : parser (ternaire/slice/assert), IR (vague 1), infer, lower.

## Risques / questions ouvertes
- 🔶 Bornes de slice négatives `xs[-1:]` (Python) — V8, ou clamp ; figer.
- 🔶 Slicing str sur frontières non-UTF8 → panic Rust ; documenter (filet I2).
