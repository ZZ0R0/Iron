# [30600] `weak()` / `Weak` + lint aliasing I3 (finition Rc)

- Version : V7 · Milestone : M6 · Statut : draft · Dépend de : 30300, 60300 · Invariants : I5, I3

## Objectif
Compléter le partage explicite (différé V6/30300) : références faibles `Weak` (casse-cycles) et le **lint
aliasing** I3 (« tu voulais peut-être partager ? »).

## Périmètre
- `weak(r) -> weak[T]` (`Rc::downgrade`) ; `upgrade(w) -> Option[shared[T]]` (`Weak::upgrade`).
- Lint aliasing (via 60300) : un auto-clone qui change une sémantique de partage → avertissement perf/correction.

## Hors-périmètre
- Ramasse-cycles automatique (I5 : `Weak` explicite, à la charge utilisateur) ; `Arc`/threads (V8).

## Comportement attendu
- `w = weak(node)` → `Rc::downgrade(&node)` ; type `weak[T]` → `std::rc::Weak<RefCell<T>>`.
- `upgrade(w)` → `w.upgrade()` (Option, I11) ; un cycle parent↔enfant via `weak` compile + libère.
- Auto-clone d'une valeur partageable → `IRN-L011 aliasing : envisager 'shared'`.

## Contrat / interface
IR : `Type::Weak(Box<Type>)`. Constructeurs `weak`/`upgrade` (built-ins) → `Rc::downgrade`/`upgrade`.
Lint aliasing dans la passe 60300 (D6).

## Source maps
Le lint aliasing porte le `Span` Iron (I8).

## Critères d'acceptation
- Un graphe avec cycle cassé par `weak` compile + s'exécute (pas de fuite logique) ; `upgrade` → Option.
- Le lint aliasing se déclenche sur le cas piège, pas sur un partage correct.

## Décomposition
→ planif : IR `Weak`, `weak`/`upgrade`, lint aliasing (intègre 60300).

## Risques / questions ouvertes
- 🔶 `weak[T]` sur `Rc<RefCell<T>>` (mutable) vs `Rc<T>` (immuable) — cohérence avec 30300 (RefCell par défaut).
