# [60300] Passe de lint réelle (I4)

- Version : V7 · Milestone : M6 · Statut : draft · Dépend de : 30200, 30400, 60100 · Invariants : I4, I8

## Objectif
Honorer I4 : une **passe de lint** Iron émettant des avertissements **perf/correction** au `Span` Iron —
aujourd'hui seul un comptage de clones brut existe (`--audit`).

## Périmètre
- Lints : variables **inutilisées**, **clones évitables** (perf), **shadowing**, code **mort** (après
  `return`), **aliasing** « tu voulais peut-être partager ? » (I3, différé V6/30300), littéral numérique
  débordant.

## Hors-périmètre
- Lints stylistiques (→ `ironc fmt`, 70600) ; lints configurables par fichier (V8).

## Comportement attendu
- `--audit` produit une liste `fichier:ligne:col [IRN-Lxxx] message` (sévérité `warn`).
- Variable assignée jamais lue → `IRN-L001 variable inutilisée 'x'` ; clone forcé par un usage multiple →
  `IRN-L010 clone évitable (envisager 'shared' ?)`.

## Contrat / interface (D6)
Nouvelle passe `lint.rs` sur AST + `TypeMap`/`OwnershipMap` → `Vec<Lint{ span, severity, code, msg }>`.
Format D6 : `Span` Iron + sévérité (`warn`/`deny`) + code `IRN-Lxxx`. Émis par le driver sous `--audit` ;
non bloquant (sauf `deny` explicite, I4).

## Source maps
Chaque lint porte un `Span` Iron → ligne:col exacte (I8).

## Critères d'acceptation
- Programme avec variable inutilisée + clone évitable + code mort → 3 lints aux bons `Span`.
- `--audit` non bloquant ; programme propre → 0 lint ; corpus reste « 0 lint perf » sauf intentionnels.

## Décomposition
→ planif : framework lint (collecte/format), lints unused/dead, lint clone/aliasing, lint shadowing.

## Risques / questions ouvertes
- 🔶 Faux positifs « clone évitable » (clone parfois nécessaire) → sévérité `warn` only, message prudent.
