# [80700] Stdlib : itertools (`enumerate`, `zip`, `reduce`, `sorted`, …)

- Version : V7 · Milestone : M3 · Statut : draft · Dépend de : 20700, 10400, 80500 · Invariants : I1, I6

## Objectif
Outils d'itération de base, absents : `enumerate`, `zip`, `reversed`, `reduce`, `sorted(key=)`, `any`, `all`.
Wrappers sur les itérateurs Rust (D2, coût nul).

## Périmètre
- `enumerate(xs) -> list[(i64, T)]` ; `zip(xs, ys) -> list[(A, B)]` ; `reversed(xs)` ; `any(xs)`/`all(xs)` ;
  `reduce(f, xs, init)` ; `sorted(xs)` / `sorted(xs, key=f)`.

## Hors-périmètre
- Itérateurs paresseux/générateurs (V8) ; `groupby`, `chain` (V8).

## Comportement attendu
- `enumerate(xs)` → `xs.into_iter().enumerate().map(|(i, x)| (i as i64, x)).collect()` (tuples, 10400).
- `zip(xs, ys)` → `xs.into_iter().zip(ys).collect()`.
- `reduce(lambda a,b: a+b, xs, 0)` → `xs.into_iter().fold(0, |a, b| a + b)`.
- `sorted(xs, key=lambda x: -x)` → tri par clé (`sort_by_key`).

## Contrat / interface
Built-ins (ou module `iter`) dispatchés à la lower → chaînes d'itérateurs. Retours tuple → dépend de 10400.
`reduce`/`sorted(key=)` prennent une closure (20700). `infer` : types de retour (list de tuples, etc.).

## Critères d'acceptation
- `enumerate(["a","b"])` → `[(0,"a"),(1,"b")]` ; `zip([1,2],[3,4])` → `[(1,3),(2,4)]`.
- `reduce(+, [1,2,3,4], 0)` → 10 ; `sorted([3,1,2])` → `[1,2,3]` ; `any`/`all` corrects.
