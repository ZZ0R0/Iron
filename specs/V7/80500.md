# [80500] Stdlib : collections (`set`, `deque`, ordered ; méthodes `dict`/`list`)

- Version : V7 · Milestone : M3 · Statut : draft · Dépend de : 20900, 80200 · Invariants : I1, I6

## Objectif
Compléter les collections : `deque`, maps ordonnées, et les **méthodes** manquantes de `dict`/`list` —
aujourd'hui squelettiques. Wrappers sur `std::collections` (D2).

## Périmètre
- `dict` : `.keys()`, `.values()`, `.items()`, `.get(k)`, `.contains(k)`, `.remove(k)`.
- `list` : `.pop()`, `.insert(i, x)`, `.remove(i)`, `.reverse()`, `.index(x)`, `.count(x)`, `.extend(ys)`.
- `deque[T]` → `VecDeque` (`push_front`/`pop_front`) ; ordered map → `BTreeMap` (D3).

## Hors-périmètre
- `Counter`/`defaultdict` (V8) ; heap/priority queue (V8).

## Comportement attendu
- `d.keys()` → `d.keys().cloned().collect::<Vec<_>>()` ; `d.get(k)` → `d.get(&k).cloned()` (Option, I11).
- `xs.pop()` → `xs.pop()` (Option) ; `xs.reverse()` → `xs.reverse()`.
- `q: deque[i64]` → `VecDeque<i64>` ; `push_front(q, x)` → `q.push_front(x)`.

## Contrat / interface
Méthodes `dict`/`list` dispatchées à la lower selon le type du receveur (extension du dispatch méthode V5).
`Type::Deque` (ou `App("deque", …)`) → `VecDeque`. `infer` : types de retour (Option pour get/pop, I11).

## Critères d'acceptation
- `d.keys()`/`.values()`/`.items()` itérables ; `d.get(absent)` → `None` ; `xs.pop()` retire+retourne.
- `deque` push/pop des deux côtés compile ; corpus inchangé.
