# [80300] Stdlib : fichiers IO (`io`)

- Version : V7 · Milestone : M5 · Statut : draft · Dépend de : 80200, 50500 · Invariants : I5, I7, I13

## Objectif
Module `io` pour lire/écrire des fichiers — IO basique absent (seul `input()` stdin). Implémenté en
**wrappers minces sur `std::fs`** (D2, pas de runtime).

## Périmètre
- `io.read_file(path) -> str` ; `io.write_file(path, content)` ; `io.read_lines(path) -> list[str]` ;
  `io.append_file(path, content)` ; `io.exists(path) -> bool`.

## Hors-périmètre
- Streams/handles, async IO, chemins typés (V8).

## Comportement attendu
- `io.read_file("data.txt")` → `std::fs::read_to_string("data.txt")?` (erreur → `IronError`, I13).
- `io.write_file("out.txt", s)` → `std::fs::write("out.txt", s)?`.
- `io.read_lines(p)` → `read_to_string(p)?.lines().map(str::to_string).collect()`.

## Contrat / interface
Module namespacé `io` (D2) : appels `io.<fn>` résolus en wrappers `std::fs`. Type de retour `str`/`list[str]`/
`bool` ; faillible → enveloppe `Result` (I11, propagation `?`). Implémenté via `.iri` curé `io.iri` + lower.

## Source maps
N/A (erreur IO = `IronError` runtime, pas de compile error).

## Critères d'acceptation
- `io.write_file` puis `io.read_file` round-trip un contenu ; `io.read_lines` découpe correctement.
- Fichier absent → `IronError` propre (pas de panic brut) ; corpus inchangé.

## Décomposition
→ planif : résolution `io.<fn>`, wrappers `std::fs`, gestion `Result`/`IronError`.

## Risques / questions ouvertes
- 🔶 Namespacing `io.read_file` : appel `Field`(base=Var "io") spécial-casé à la lower (module réservé).
