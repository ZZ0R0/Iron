# [20900] Type `set`

- Version : V7 · Milestone : M2 · Statut : draft · Dépend de : 20100, 10600 · Invariants : I1, I6

## Objectif
Ensembles — collection sans doublon à test d'appartenance O(1) — absents aujourd'hui (seuls list/dict).

## Périmètre
- Type `set[T]` ; littéral `{1, 2, 3}` (sans `:`, distingué de dict) ; constructeur `set([…])` ;
  opérations : `add`, `in`, union `|`, intersection `&`, différence `-`, `len`.

## Hors-périmètre
- `frozenset` ; ensembles ordonnés (→ 80500, `BTreeSet`).

## Comportement attendu
- `s: set[i64] = {1, 2, 3}` → `let s: HashSet<i64> = HashSet::from([1i64, 2i64, 3i64]);` (D3).
- `x in s` → `s.contains(&x)` ; `add(s, x)` → `s.insert(x)`.
- `a | b` → `&a | &b` (union) ; `a & b` → intersection ; `a - b` → différence.

## Contrat / interface
IR (fondation D0) : `Type::Set(Box<Type>)` ; littéral set réutilise `ExprKind::Set` ou DictLit sans valeurs.
`infer` : `set[T]`. `lower_type` → `std::collections::HashSet<T>`. Opérateurs ensemblistes via `BinOp`
réutilisés (`|`,`&`,`-`) dispatché sur le type set. Élément `Hash + Eq` (filet `rustc`).

N/A.

## Critères d'acceptation
- `{1,2,2,3}` → ensemble de taille 3 ; `2 in {1,2,3}` → true ; `{1,2} | {2,3}` → `{1,2,3}`.
- `set` en paramètre/retour, `add` compilent + s'exécutent ; corpus inchangé (dict `{k:v}` non cassé).

## Décomposition
→ planif : IR (vague 1), parser (littéral `{…}` set vs dict), infer, lower (HashSet + ops).

## Risques / questions ouvertes
- 🔶 `{}` vide = dict ou set ? → `dict` (rétro-compat) ; set vide = `set([])`.
- 🔶 Opérateurs `|`/`&`/`-` surchargés set vs bit-à-bit (10700) — dispatch par type à la lower.
