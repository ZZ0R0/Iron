# [80600] Stdlib : combinateurs `Option` / `Result`

- Version : V7 · Milestone : M3 · Statut : draft · Dépend de : 20400, 20700 · Invariants : I11, I13

## Objectif
Méthodes idiomatiques sur `Option`/`Result` (`map`, `unwrap_or`, …) — aujourd'hui seuls `?` et `match`
existent. Wrappers directs sur les méthodes Rust (D2, coût nul).

## Périmètre
- `Option` : `.map(f)`, `.and_then(f)`, `.unwrap_or(d)`, `.unwrap_or_else(f)`, `.is_some()`, `.is_none()`, `.get_or(d)`.
- `Result` : `.map(f)`, `.map_err(f)`, `.unwrap_or(d)`, `.is_ok()`, `.is_err()`, `.ok()` (→ Option).

## Hors-périmètre
- `?` sur Option en fn Result (conversion) ; combinateurs exotiques (`zip`, `flatten`) → V8.

## Comportement attendu
- `find(xs).map(lambda x: x + 1)` → `find(xs).map(|x| x + 1)`.
- `find(xs).unwrap_or(0)` → `find(xs).unwrap_or(0i64)`.
- `r.is_ok()` → `r.is_ok()` ; `r.ok()` → `r.ok()` (Result→Option).

## Contrat / interface
Dispatch méthode à la lower sur receveur `Type::Option`/`Type::Result` (extension du dispatch V5). `infer` :
`.map` → `Option<U>`/`Result<U>` ; `.unwrap_or` → `T` ; `.is_*` → Bool. Closures réutilisées (20700).

## Critères d'acceptation
- `find([1,2,3]).map(lambda x: x*10).unwrap_or(-1)` → valeur correcte ou -1.
- `safe_div(…).is_ok()`, `.ok()`, `.map_err(…)` compilent + s'exécutent ; corpus inchangé.

## Décomposition
→ planif : dispatch méthodes Option, méthodes Result, infer des retours.

## Risques / questions ouvertes
- 🔶 `.map(f)` infère `U` depuis la closure — best-effort (rustc filet) ; type de la closure laissé à Rust (I2).
