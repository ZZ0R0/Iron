# [50600] Dépendances de crates : déclaration + résolution + auto-`bind`

- Version : V7 · Milestone : M4 · Statut : draft · Dépend de : 50500, 70300 · Invariants : I7, I9

## Objectif
Utiliser une **vraie crate Rust** depuis Iron de bout en bout : déclarer la dépendance, la résoudre via
cargo, et obtenir ses bindings — le déblocage interop central de V7.

## Périmètre
- Dépendances déclarées dans `ironc.toml` `[dependencies] serde_json = "1"` (cf. 70300).
- `ironc` injecte la dep dans le `Cargo.toml` généré ; `bind` peut cibler une crate de deps.
- Stratégie **hybride** (D5) : auto-`bind` (rustdoc-json) ou `.iri` curé fourni (`bindings/serde_json.iri`).

## Hors-périmètre
- Résolution de versions sémantiques fine / lockfile Iron (délégué à cargo) ; features de crate (V8).

## Comportement attendu
- `[dependencies] rand = "0.8"` → `Cargo.toml` généré contient `rand = "0.8"` ; `use "rand.iri"` + appel compile.
- `.iri` curé prioritaire si présent ; sinon tentative auto-`bind` ; sinon erreur claire « crate non bindée ».

## Contrat / interface
`driver` : lit `[dependencies]` du manifeste → `crates` (déjà passé à `emit_project`). Résolution `.iri` :
`bindings/<crate>.iri` curé > auto-`bind`. `bind` peut prendre une crate de `~/.cargo` (dep résolue).

## Critères d'acceptation
- Un projet déclarant `serde_json` + `.iri` curé → `json.parse` compile + s'exécute (cf. 80400).
- Dep absente du manifeste → erreur « dépendance non déclarée » ; corpus mono-fichier inchangé.

## Décomposition

## Risques / questions ouvertes
- 🔶 Auto-`bind` d'une crate tierce = réseau + nightly + temps — réservé à l'opt-in ; `.iri` curé par défaut (D5).
