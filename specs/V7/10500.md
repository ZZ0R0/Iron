# [10500] f-strings / interpolation de chaînes

- Version : V7 · Milestone : M1 · Statut : draft · Dépend de : 10100, 10200 · Invariants : I6, I9, I10

## Objectif
Interpolation de chaînes `f"{x} = {y}"` — attendu de tout langage moderne, aujourd'hui absent (seul
`concat`/`format` manuel).

## Périmètre
- Littéral `f"…{expr}…"` avec expressions arbitraires entre accolades ; échappement `{{`/`}}` ;
  format simple `{x}` (Display). Désucrage → `format!`.

## Hors-périmètre
- Spécificateurs de format `{x:.2f}` (V8, sucre sur `format!` width/precision) ; f-strings multi-lignes.

## Comportement attendu
- `f"{name} a {age} ans"` → `format!("{} a {} ans", name, age)`.
- `f"somme = {a + b}"` → `format!("somme = {}", a + b)`.
- `f"{{litéral}}"` → `format!("{{litéral}}")` (accolades littérales).

## Contrat / interface
Lexer : reconnaître le préfixe `f"…"` → token `FString` portant la liste **parts** (littéraux + sous-sources
d'expression). Parser : re-lexer/parser chaque sous-expression. IR : `ExprKind::FString(Vec<FStringPart>)`
où `Part = Lit(String) | Expr(Box<Expr>)`. `lower` → `format!(fmt, args…)` (I10, `TokenStream`).

## Source maps
Marqueur sur l'expression `format!` (instruction). Erreur dans une sous-expression → `Span` du `f"…"`.

## Critères d'acceptation
- `f"{name} a {age} ans"` avec name="Iron", age=1 → `Iron a 1 ans`.
- `f"{a+b}"` (a=2,b=3) → `5` ; `f"{{x}}"` → `{x}` ; corpus inchangé.

## Décomposition
→ planif : lexer (capture f-string), parser (sous-expressions), IR (vague 1), lower (`format!`).

## Risques / questions ouvertes
- 🔶 Imbrication d'accolades dans les sous-expressions (dict/set littéraux) — capture équilibrée requise.
