# [24500] Const-génériques (valeur au niveau type : `[u8; N]`, `GenericArray<u8, U32>`, `Const<N>`)

- Version : V13 · Milestone : M13 · Statut : **cadrage** · Dépend de : [24000], [24100], [24200] · Invariants : I2, I6, I10
- **Tête d'affiche V13.** Le plus gros levier (jusqu'à 8 crates) ET le plus dur. Deux sous-cas nets ci-dessous.

## Objectif
Référencer/construire des types paramétrés par une **valeur** (un nombre N) portée au niveau type : tailles
d'octets de crypto (`GenericArray<u8, U32>`, `Key<C>`, `Nonce<C>`) et dimensions de matrices (`Matrix<T,
Const<3>, Const<1>>`). V12 a fait `[u8; N]` **littéral** ([24200], blake3). V13 généralise.

## Sous-cas A — tailles d'octets (TRACTABLE) → aes-gcm, chacha20
- **Constat** : la matérialisation `list[u8] → GenericArray<u8, N>` n'a **pas besoin de N** — `from_slice(&v)`
  / `(&v[..]).try_into()` infère la taille depuis la signature (rustc). Exactement le mécanisme [24200].
- **Décision** : étendre la sentinelle **`@arr`** à tout **tableau d'octets de taille fixe** :
  - `[u8; N]` (déjà) ;
  - `GenericArray<u8, …>` (résoudre l'alias `Key<C>`/`Nonce<C>`/`Tag<C>` → `GenericArray<u8, …>` via B33, puis `@arr`) ;
  - reconnaissance dans `map_type` : un `resolved_path` `GenericArray`/`Key`/`Nonce`/`Tag` dont le 1ᵉʳ arg (ou
    l'élément) est `u8` → `@arr`.
- **Type-cipher** (`Aes256Gcm = AesGcm<Aes256, U12>`) : alias → handle appliqué utilisable. Args typenum
  non-octets (`U12`) **opaques** (`Extern("typenum::U12")`) — leur valeur est inutile à la construction.

## Sous-cas B — dimensions de matrices (DUR, peut rester partiel) → nalgebra, ndarray, rustfft, rapier2d
- `Vector3<T> = Matrix<T, Const<3>, Const<1>, …>` ; `Vector3::new(x,y,z)` = **fn par-dimension** (macro), pas
  un `new(T,T,T)` générique → le binder ne la capte pas aujourd'hui.
- **Piste (assumée non générale)** : **table d'alias-dimension connus** (`Vector2..6`, `Matrix2..6`, `Point2/3`)
  → exposer leurs ctors `new(x, …)` avec la bonne arité + `Const<N>`/typenum résolu pour le lowering.
- **Encodage const → Rust** : si un N **doit** être émis explicitement (rare hors from_slice), ajouter
  `Type::ConstN(u64)` ; lowering `ConstN(N)` → `N` (position const-générique) **ou** `typenum::U{N}` (position
  typenum), selon ce que le binder a vu. Pour A, **pas nécessaire** (taille inférée).
- **Risque** : au-delà des dims tabulées, ça reste bloqué. **Honnête : nalgebra/ndarray peuvent rester partiels.**

## Hors-périmètre
- Arithmétique sur const-génériques (`[T; N+1]`), const-génériques **utilisateur** (Iron `class Foo[const N]`).
- Dimensions dynamiques (`Dyn`), storages exotiques.

## Décision d'ABI (figée)
1. **Octets** : `@arr` étendu (GenericArray<u8,_>/Key/Nonce/Tag) — matérialisation `try_into`/`from_slice`,
   **taille inférée**. **Pas de `ConstN`.**
2. **Dimensions** : table d'alias-dimension → ctors explicites ; `Type::ConstN(u64)` **seulement si** une taille
   doit être émise (et non inférée). Additif, comme `ExternApp`.

## Questions ouvertes

- ❓ `GenericArray<T, N>` pour `T ≠ u8` (rare) — hors périmètre initial.

- nalgebra : `Vector3.new(1.0,2.0,3.0).norm()` (run réel) **si** la table aboutit ; sinon **noté partiel**.
