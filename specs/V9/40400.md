# [40400] Auto-wrap I11 complet (`Ok`/`Some` sur appels externes/méthodes)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 40200, 20200 · Invariants : I11

## Objectif
Combler le **trou I11** trouvé en V8 : `return <appel externe/méthode booléen>` dans une fn `Result[bool]`
n'est **pas** auto-emballé en `Ok(...)` → forçait le `ok(...)` manuel. L'auto-wrap (déclaré vs effectif)
doit couvrir **tous** les retours, y compris les appels externes et de méthodes.

## Périmètre
- Étendre l'analyse de flux `effective_ret` + le wrap `lower` : un `return X` dans une fn déclarée
  `Result[T]`/`Option[T]`, où `X : T` (et non déjà `Result`/`Option`), est emballé `Ok(X)`/`Some(X)`.
- Couvrir : appels externes (`r.is_match(t)`), méthodes externes, expressions composées.
- Symétrique pour `Option` (`return None`/valeur).

## Hors-périmètre
- `IronError` typé (I13). Le `?`/`try` (déjà OK).

## Comportement attendu
```
def check(p: str, t: str) -> Result[bool]:
    r = Regex.new(p)?
    return r.is_match(t)          # ← auto-emballé Ok(...), plus besoin de ok(...)
```
→ `return Ok(r.is_match(&t));`

## Contrat / interface
`infer`/`flow` : `effective_ret` reconnaît que le corps « est dans un contexte Result » (présence de `?`) et
que le `return X` final fournit l'inner `T`. `lower` : emballe `Ok/Some` quand déclaré=Result/Option et
effectif=inner.

## Source maps
I8 : le `Ok(...)`/`Some(...)` injecté hérite du `Span` du `return`.

## Critères d'acceptation
- La demo regex V8 sans `ok(...)` (`return r.is_match(t)`) compile + s'exécute.
- `return None` et `return valeur` dans une fn `Option[T]` → `None`/`Some(valeur)` corrects.
- Corpus inchangé (les wraps existants non régressés).

## Décomposition
→ planif : extension `effective_ret`/wrap aux appels externes/méthodes, tests Result + Option.

## Risques / questions ouvertes
- 🔶 Ambiguïté : un `return expr` où `expr` est **déjà** `Result` (pas à emballer) vs inner (à emballer) →
  trancher par le type inféré de `expr` vs l'inner déclaré.
