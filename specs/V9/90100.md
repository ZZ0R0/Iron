# [90100] Métrique de vérité CHIFFRÉE (correction Iron→Rust + coût clone)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 90200, 90400, 60500 · Invariants : I4

## Objectif
Produire **enfin** la **métrique-cœur chiffrée** (différée depuis V6 : « refuser un chiffre sur données
insuffisantes plutôt qu'en publier un faux »). Le langage gèle en V9 → le corpus + la batterie 30-vrais-crates
fournissent la base suffisante. Deux chiffres : **correction sémantique `Iron → Rust généré`** et **coût du
clone-fallback** (I4).

## Périmètre
- **Correction** : sur le corpus complet (fixtures + 30 projets V7 + 30 vrais crates 90400), % de programmes
  dont la sortie Iron == oracle (Python pur ou attendu figé). Décompte des écarts, catégorisés.
- **Coût clone-fallback** : nombre de `.clone()` générés / programme, part **évitable** (lien lint 60500),
  sur le corpus — la mesure de « combien la sémantique-valeur coûte » (I4).
- **Rapport** : `ironc bench` ou un script agrégateur → tableau chiffré + tendance.

## Hors-périmètre
- Benchmarks de **vitesse d'exécution** (Iron hérite des perfs Rust ; hors métrique-cœur).

## Comportement attendu
Un rapport : « Correction : 158/160 programmes (98.8%) ; 2 écarts (catégorie : formatage flottant). Clones :
moyenne 1.4/programme, dont 0.3 évitables (I4). »

## Contrat / interface
Script/commande agrégateur sur `tests/` : compile+run chaque programme, diff vs oracle, compte clones
(grep `.clone()` du Rust généré) + clones évitables (60500). Sortie : tableau + JSON.
