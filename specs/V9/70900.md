# [70900] Module `thread` : `spawn`/`join` + closures `move` Send-aware

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 30700, 20700 · Invariants : I2, I5

## Objectif
Donner le **threading natif** en Iron (prouvé faisable en V8 via `rust{}` → ici en Iron pur). Module
`thread` (wrappers `std::thread`) + closures `move` que `rustc` accepte de passer entre threads (Send).

## Périmètre
- **`thread.spawn(f)`** → `std::thread::spawn(move || f())` ; renvoie un handle.
- **`handle.join()`** → `.join().unwrap()` ; renvoie la valeur du thread.
- **`thread.scope(...)`** (optionnel) → `std::thread::scope` (threads empruntant la pile).
- **Closures `move`** : une lambda passée à `spawn` capture par **move** (Send-aware) ; l'état partagé mutable
  **exige** `shared_sync` (30700) — un `shared`/`Rc` est rejeté par `rustc` (I2 filet), avec message Iron clair.
- `rust{}` reste l'échappatoire pour les patterns exotiques (select, pools custom).

## Hors-périmètre
- `async`/tâches (21200). Pools de threads (→ binding `rayon` / `rust{}`).

## Comportement attendu
```
import thread

def parallel_sum(n: i64) -> i64:
    mid = n / 2
    h1 = thread.spawn(lambda: range_sum(1, mid))
    h2 = thread.spawn(lambda: range_sum(mid + 1, n))
    return h1.join() + h2.join()
```
→ `std::thread::spawn(move || range_sum(1, mid))` … `.join().unwrap()`.

## Contrat / interface
`.iri`/stdlib bénie : `thread.spawn`/`join`/`scope`. `lower` : closure → `move ||`, handle → `JoinHandle`,
`join` → `.join().unwrap()`. Détection : capture d'un `shared` (Rc, !Send) dans un `spawn` → **erreur Iron**
« utilise `shared_sync` pour partager entre threads » (avant le rejet `rustc`).

## Source maps
I8 : `spawn`/`join` portent le `Span` ; une erreur `Send` `rustc` remonte au `Span` du `spawn`.

## Critères d'acceptation
- `parallel_sum` en **Iron pur** (la demo V8 `rust{}` réécrite) → compile + s'exécute, résultat juste.
- Partage via `shared_sync` entre threads compile ; via `shared` → erreur Iron explicite (test négatif).
- 0 `unsafe`.

## Décomposition
→ planif : `thread.spawn`/`join`, closure `move`, détection `shared` non-Send, message d'erreur.

## Risques / questions ouvertes
- 🔶 Type de retour du thread (générique) → inférence du `T` de `JoinHandle<T>` depuis la lambda.
- 🔶 Lambdas Iron capturant beaucoup d'état → `move` peut surprendre ; documenter.
