# [71100] LSP : serveur de langage (diagnostics, complétion, go-to-def, hover)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 60600, 21100, 60700 · Invariants : I8

## Objectif
Le **grand levier DX** : un serveur **LSP** pour Iron → diagnostics live, complétion, go-to-définition,
hover, rename, dans VS Code / tout éditeur LSP. Sans LSP, un langage « fini » ne l'est pas vraiment pour un
dev moderne.

## Périmètre
- **Serveur `ironc lsp`** (stdio, protocole LSP) bâti sur le pipeline existant (lex/parse/infer).
- **Diagnostics** : erreurs lexer/parser/inférence (60600) + remontées `rustc` mappées (I8) → `Diagnostic`
  LSP à la bonne position.
- **Complétion** : méthodes d'un type (struct/extern), fns en scope, méthodes de crates bindés (51600).
- **Hover** : type inféré d'une expression (depuis la `TypeMap`).
- **Go-to-def / rename** : structs/fns/variables (via les `NodeId`/spans).

## Hors-périmètre
- Refactorings avancés, formatage à la frappe (déléguer à `fmt` 71000).
- Indexation incrémentale fine (recompiler le fichier suffit au v0).

## Comportement attendu
Édition dans VS Code → soulignement des erreurs Iron en temps réel ; `r.` propose `is_match`/`find` (méthodes
du `Regex` bindé) ; hover sur une variable montre son type Iron.

## Contrat / interface
`lsp.rs` (crate/bin) : boucle LSP, réutilise `infer`/spans/`Bindings`. Mappe `Span` Iron ↔ positions LSP
(ligne/col). S'appuie sur 60600 (erreurs Iron) et 51600 (méthodes de crates pour la complétion).

## Source maps (I8)
Cœur du LSP : la correspondance `Span` Iron ↔ position éditeur **est** la source-map (I8). Les diagnostics
`rustc` remontés doivent pointer la bonne position Iron.

## Critères d'acceptation
- `ironc lsp` répond aux requêtes `initialize`, `textDocument/didChange` (diagnostics), `completion`, `hover`,
  `definition` sur un fichier de test (test d'intégration LSP scripté).
- Diagnostics positionnés correctement (erreur d'inférence + remontée rustc).
- Complétion propose les méthodes d'un type bindé.

## Décomposition
→ planif : boucle LSP stdio, diagnostics, complétion (scope + méthodes), hover (TypeMap), go-to-def, test.

## Risques / questions ouvertes
- 🔶 Performance (recompiler à chaque frappe) → debounce + cache AST. Acceptable au v0 sur fichiers moyens.
- 🔶 Complétion des méthodes de crates exige le `.iri` chargé (binding résolu) — lier au cache 70700.
