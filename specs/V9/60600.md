# [60600] Erreurs de type niveau Iron (avant `rustc`)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 20100, 21100, 60100 · Invariants : I8, I6

## Objectif
Détecter les **erreurs de type au niveau Iron** (différé V7/60400), **avant** `rustc`, avec des messages
clairs et un `Span` Iron — au lieu de laisser passer puis remonter une erreur Rust obscure. Prérequis d'un
bon LSP (71100) et d'une DX « finie ».

## Périmètre
- **Vérifications** : arité d'appel, type des arguments (fns user, méthodes, **méthodes externes** 21100),
  champ inexistant, méthode inexistante (avec « méthodes disponibles : … »), incompatibilité d'opérateur,
  index sur non-indexable, mismatch de retour vs déclaré.
- **Messages** : `Span` Iron précis + attendu/trouvé + suggestion quand possible.
- Reste **optimiste** (I2) : ce qui n'est pas prouvé faux passe à `rustc` (filet) ; on ne **bloque** que sur
  une erreur **certaine**.

## Hors-périmètre
- Inférence HM complète (0.1%). Vérification de l'ownership (→ resolve/lint 60500).

## Comportement attendu
```
r.is_match(123)      # erreur Iron : is_match attend `str`, trouvé `i64`  (Span sur 123)
p.unknown()          # erreur Iron : méthode `unknown` inconnue sur `Point` ; dispo : move, dist2
```

## Contrat / interface
`typecheck.rs` (ou extension `infer`) : passe produisant `Vec<TypeError { span, msg }>` ; consommée par la
CLI (échec de compilation) et le LSP (diagnostics 71100). Liste les méthodes dispo via `Bindings`/`Methods`.

## Source maps (I8)
Chaque `TypeError` porte un `Span` Iron exact (c'est le point : ne plus dépendre de la remontée `rustc`).

## Critères d'acceptation
- Les erreurs typiques (mauvais arg, méthode inconnue, mauvais retour) → message Iron clair **avant** `rustc`.
- Les fixtures négatives existantes (`type_error`) → message Iron, pas une erreur Rust brute.
- Aucun faux positif sur le corpus (les programmes valides passent).

## Décomposition
→ planif : vérif arité/args/champs/méthodes/opérateurs/retour, messages + Span, intégration CLI/LSP, tests.

## Risques / questions ouvertes
- 🔶 Rester **optimiste** (I2) : ne bloquer que sur l'erreur certaine, sinon laisser `rustc` trancher — éviter
  les faux positifs qui rejetteraient du code valide.
