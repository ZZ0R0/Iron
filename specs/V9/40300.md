# [40300] Fix `try/except` + hoisting (capture non-initialisée)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 40100 · Invariants : I9, I10, I11

## Objectif
Lever la **limite try/except** documentée (V7, confirmée V8) : une variable assignée dans un `try` et lue
**après** échoue (`used binding isn't initialized`). Cause : le corps du `try` est une **IIFE closure** qui
capture la variable hoistée (non-initialisée) → Rust refuse. Le pattern Python `try: x = f() except: …;
use(x)` doit marcher.

## Périmètre
- Repenser le désucrage `try/except` pour que les variables assignées dans le `try` soient **visibles et
  initialisées** après (selon le flux).
- Option A : ne pas utiliser d'IIFE-closure mais un `match` sur un bloc `Result` **inline** (pas de capture).
- Option B : hoister les écritures hors de l'IIFE (la closure retourne les valeurs).
- Conserver la sémantique : `except e:` attrape l'`IronError` ; `?`/`raise` propagent dans le `try`.

## Hors-périmètre
- `finally` (non encore au langage) ; exceptions typées (I13 : `IronError` unifié).

## Comportement attendu
```
try:
    r = compile(pattern)          # assigné dans le try
    n = r.count()
except e:
    n = 0
print(n)                          # n lisible et initialisé
```
→ désucrage sans capture non-init (match sur Result inline, ou valeurs retournées par la closure).

## Contrat / interface
`lower` : nouveau désucrage `StmtKind::TryExcept` → bloc `match { Ok(_) => …, Err(e) => <handler> }` où les
écritures du `try` portent sur les locaux hoistés **directement** (pas via une closure capturante).

## Source maps
I8 : chaque stmt du `try`/`except` garde son `Span` ; pas de régression de la remontée.

## Critères d'acceptation
- `try: x = f(); except: x = d` puis `use(x)` compile + s'exécute (les deux branches).
- La demo regex V8 (qui contournait via fn `Result`) marche **avec `try/except` direct** (réécrite).
- Corpus + gate binding inchangés (pas de régression du désucrage existant).

## Décomposition
→ planif : nouveau désucrage try/except sans IIFE-capture, tests des deux branches + variables.

## Risques / questions ouvertes
- 🔶 Flux complexe (assignation conditionnelle dans le `try`) → garantir l'initialisation sur tous les chemins
  ou exiger un défaut dans l'`except`. Documenter la règle.
