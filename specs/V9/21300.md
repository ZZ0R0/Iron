# [21300] Inférence élargie : HOF fiable + trous résiduels

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 20100, 20500, 20700 · Invariants : I6

## Objectif
Combler les **trous d'inférence** qui rendent la surface « plus étroite et coupante que Python » (constaté
V7/V8) : surtout les **HOF utilisateur** (param-fonction *appelé* mal inféré), et quelques ambiguïtés.

## Périmètre
- **HOF utilisateur fiable** : un param appelé (`f(x)` dans le corps, y compris dans une **compréhension**)
  → inféré `Type::Fn` correctement (V7 : seul `map`/`filter` marchait ; un `def apply(f, xs)` échouait).
- **Propagation inter-fonctions** : le type d'un param-fonction déduit de son **usage** (arité, types des
  args passés) plutôt que le défaut `i64→i64`.
- **Ambiguïtés numériques** résiduelles (annotation vs défaut) clarifiées.
- **`list()`/`set()`/`dict()` coercitions** manquantes (V8 : `list(map(...))` échouait) → ajouter.

## Hors-périmètre
- Inférence Hindley-Milner **complète** (0.1%, D6) — on reste sur l'inférence locale + flux dirigée par
  l'usage, pas un solveur global.

## Comportement attendu
```
def apply(f, xs: list[i64]) -> list[i64]:
    return [f(x) for x in xs]        # f inféré fn(i64)->i64 (appelé dans la compréhension)
squared = apply(lambda x: x * x, nums)
items = list(map(str, nums))         # list(...) coercition
```

## Contrat / interface
`infer/params.rs` : détection « param appelé » récursive (corps + compréhensions + lambdas) → `Type::Fn` ;
signature déduite des sites d'appel. `infer/local.rs` : `list`/`set`/`dict` builtins de coercition.

## Critères d'acceptation
- `def apply(f, xs)` avec `f` appelé dans une compréhension → compile (le cas qui échouait en V7).
- `list(map(f, xs))` compile.
- Aucune régression du corpus (les inférences existantes tiennent).
