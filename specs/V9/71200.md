# [71200] `ironc repl` : éval incrémental

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 40100, 70100 · Invariants : I9

## Objectif
Un **REPL** Iron (`ironc repl`) pour l'exploration interactive — confort attendu d'un langage « fini ».
Approche pragmatique : **compile-and-run** par snippet (pas un interpréteur — Iron n'en a pas, I9).

## Périmètre
- Boucle lecture-éval-affichage : chaque entrée = un fragment Iron accumulé à une session (les `def`/`x = …`
  précédents restent en scope), recompilé + exécuté, dernière expression affichée.
- **Stratégie** : maintenir un « programme accumulé » ; chaque ligne ré-émet un `main` qui rejoue l'état +
  la nouvelle ligne. Simple, robuste (réutilise tout le pipeline + `cargo`).
- Affichage de la dernière expression (auto-`print` si imprimable, règles de sortie connues).

## Hors-périmètre
- Hot-reload / état persistant en mémoire (on recompile — coût accepté au v0).
- Édition multiligne avancée, complétion (→ LSP 71100).

## Comportement attendu
```
>>> x = 21
>>> x * 2
42
>>> def sq(n: i64) -> i64: return n * n
>>> sq(x)
441
```

## Contrat / interface
`repl.rs` : accumulateur de définitions + dernière expression → programme Iron → `driver::run` → capture
sortie. Gestion d'erreur : une ligne fautive n'invalide pas la session (rollback de l'accumulateur).

## Source maps
N/A (interactif) ; les erreurs gardent leur `Span` relatif à la ligne saisie.

## Critères d'acceptation
- Session : définir une variable, l'utiliser, définir une fn, l'appeler → sorties correctes (test scripté).
- Une ligne fautive → message d'erreur, session **préservée** (rollback).

## Décomposition
→ planif : accumulateur + ré-émission, capture sortie, rollback sur erreur, test scripté.

## Risques / questions ouvertes
- 🔶 Latence (recompile par ligne via cargo) → acceptable pour un REPL exploratoire ; cache cargo aide.
- 🔶 Effets de bord répétés (un `print` rejoué à chaque ligne) → n'afficher que la **nouvelle** sortie (diff).
