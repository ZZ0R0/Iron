# [51900] Attributs Rust pass-through (`@derive`/`@repr`/`@inline`)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 10200, 40100 · Invariants : I6, I10

## Objectif
La **3ᵉ jambe de l'interop** : laisser Iron **piloter la codegen Rust** en posant des **attributs** `#[…]`
sur ses items. Iron auto-dérive déjà `#[derive(Debug, Clone)]` ; cette spec ouvre le **contrôle** : derives
custom (surtout `Serialize`/`Deserialize` → **structs Iron ↔ JSON** via serde), `repr(C)` (FFI/export 51800),
`inline` (perf). Désucrage trivial : pass-through TokenStream (I10), aucune sémantique nouvelle.

## Périmètre
- **Syntaxe Iron** : décorateur façon Python `@<attr>(<args>)` au-dessus d'une `class`/`def`/`enum` :
  `@derive(Serialize, Deserialize)`, `@repr(C)`, `@inline`, `@inline(never)`.
- **Lowering** : `@<attr>(<args>)` → `#[<attr>(<args>)]` **verbatim** (TokenStream) sur l'item Rust généré,
  **en plus** des derives auto (`Debug, Clone`) — fusion intelligente des `derive` (pas de doublon).
- **AST** : `Item` porte `attrs: Vec<String>` (gelé en fondation 1.1).
- **Cas béni** : `@derive(Serialize, Deserialize)` + une dépendance `serde` → `serde_json::to_string(&obj)` /
  `from_str::<MaStruct>` (instance-pinning 51400) sur une struct **Iron**.

## Hors-périmètre
- Attributs **arbitraires non sûrs** (`#[no_mangle]`, `unsafe` indirect) → autorisés mais à la charge de
  l'utilisateur (I2 reste : Iron n'émet pas d'`unsafe`, mais un attribut pass-through est sous sa responsabilité).
- Macros procédurales custom autres que les derives std/serde courantes → best-effort (le crate doit être lié).

## Comportement attendu
```
@derive(Serialize, Deserialize)
class Point:
    x: i64
    y: i64
```
→
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Point { pub x: i64, pub y: i64 }
```
Usage : `s = to_json(p)` (serde sur une struct Iron) ; `p = from_json(s)?`.

## Contrat / interface
`lex`/`parse` : décorateur `@attr(args)` (réutilise `@`, façon Python) attaché à l'item suivant.
`ir.rs` : `Item.attrs: Vec<String>`. `lower` : émet `#[attrs…]` + fusionne les `derive` (auto + user).

## Source maps
N/A (l'attribut annote un item ; pas d'expression exécutable). L'item garde son `Span` (I8).

## Critères d'acceptation
- `@derive(Serialize, Deserialize)` sur une struct Iron + serde lié → `to_json`/`from_json` d'un objet Iron
  compile + round-trip correct (test e2e).
- `@repr(C)` émis ; `@inline` émis ; fusion des `derive` (pas de `Debug` en double).
- 0 `unsafe` généré par Iron lui-même (I2 ; l'attribut user reste sa responsabilité).

## Décomposition
→ planif `2.6` : décorateur `@attr(args)`, `Item.attrs`, lowering + fusion derive, demo serde struct↔JSON.

## Risques / questions ouvertes
- 🔶 Collision décorateur Iron vs futurs « vrais » décorateurs Python (`@property`…) → réserver `@` aux
  attributs Rust au v0 ; les décorateurs comportementaux = hors-périmètre (0.1%).
- 🔶 Fusion des `derive` : parser les args de `@derive(...)` pour dédoublonner avec `Debug, Clone` auto.
