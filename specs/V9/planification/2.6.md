# [2.6] Attributs Rust pass-through (`@derive`/`@repr`/`@inline`)

- Spec parente : 51900 · Version : V9 · Dépend de : 1.1 · Statut : todo · **Vague 2** (parallélisable — frontend/lower)

## But
Décorateur Iron `@<attr>(args)` → `#[<attr>(args)]` sur l'item Rust ; débloque serde sur les structs Iron.

## Fichiers touchés
`src/lex.rs`+`src/parse.rs` (décorateur `@attr(args)` attaché à l'item) · `src/ir.rs` (`Item.attrs: Vec<String>`,
gelé en 1.1) · `src/lower.rs` (émission `#[…]` + fusion des `derive` auto+user).

## Étapes
1. Lexer/parser : `@<ident>(<tokens>)` (ou `@<ident>`) au-dessus d'une `class`/`def`/`enum` → `Item.attrs`.
2. lower : émettre `#[attr…]` verbatim ; **fusionner** les `derive` (auto `Debug, Clone` + user) sans doublon.
3. Demo serde : `@derive(Serialize, Deserialize)` sur une struct Iron + `to_json`/`from_json` (instance-pinning 51400).

## Critère de done
`@derive(Serialize, Deserialize)` sur une struct Iron → round-trip JSON correct (e2e) ; `@repr(C)`/`@inline`
émis ; pas de `Debug` en double ; corpus + gate binding VERTS.

## Notes
Pass-through TokenStream (I10), aucune sémantique nouvelle. `@` réservé aux attributs Rust au v0 (décorateurs
comportementaux Python = 0.1%). Ownership : surtout frontend + lower.
