# [70800] Registre de bindings curés + `ironc add`

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 50900, 70700 · Invariants : I7

## Objectif
Donner à Iron son **écosystème sans armée de devs** : un **registre de `.iri` curés** mutualisés (modèle
**@types / nimble / wheels**), pour les crates dont l'auto-bind ne suffit pas (traits user, builders
complexes, async). Un humain curé **une fois** ; tout le monde réutilise. C'est la pièce qui rend Iron
« batteries included » sur les crates clés.

## Périmètre
- **Format & emplacement** : un dossier `bindings/` versionné (dans le dépôt Iron ou un repo séparé) :
  `bindings/<crate>/<version>.iri` (curé, peut compléter l'auto-bind avec instance-pinning + idiomes).
- **`ironc add <crate>`** : ajoute le crate à `ironc.toml` + récupère le `.iri` curé du registre (sinon
  auto-bind, 70700).
- **Seed initial** : l'équipe cœur curé le **top-N** (serde_json, regex, rand, chrono, reqwest/ureq, clap,
  itertools, anyhow…) — `.iri` fournis dans le registre.
- **Priorité de résolution** (70700) : `.iri` curé du registre > auto-bind caché.

## Hors-périmètre
- Hébergement réseau du registre (un dossier local/dépôt suffit au v0).
- Versioning sémantique fin (compat 1-1 version au v0).

## Comportement attendu
- `ironc add serde_json` → `[dependencies] serde_json = "1"` dans `ironc.toml` + `.iri` curé en place.
- `import serde_json` utilise le `.iri` curé (couverture > auto seul).

## Contrat / interface
`bind`/`driver` : résolveur de registre (`bindings/<crate>/<ver>.iri`) ; `ironc add` édite `ironc.toml`.
Le `.iri` curé est un `.iri` v2 (50900) normal — il peut être **auto-bind + édité à la main**.

## Critères d'acceptation
- `ironc add regex` + `import regex` → programme compile+run, `.iri` venant du registre.
- ≥ 5 crates « bénis » curés dans le registre, chacun avec ≥ 1 programme de test (90400).
- Un crate absent du registre → fallback auto-bind (70700), pas d'erreur.
