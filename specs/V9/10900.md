# [10900] Générateurs `yield` → itérateurs Rust

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 10200, 40100, 20300 · Invariants : I6, I9, I10

## Objectif
Supporter les **générateurs** Python (`yield`) — une feature de surface manquante pour « cloner Python ».
Mapper une fonction à `yield` vers un **itérateur Rust** (struct + état, ou `impl Iterator`). **Point le plus
risqué de V9** (D5) : le mapping général des coroutines est dur.

## Périmètre
- **Cas cadrés (v0)** : `yield` dans une **boucle simple** sur un itérable / une plage → désucrage vers un
  `impl Iterator` (chaîne d'itérateurs `map`/`filter`/`flat_map`) **sans machine à états manuelle** quand
  possible.
- `for x in gen():` consomme l'itérateur produit.
- **Syntaxe** : `def g(...) -> iter[T]:` + `yield e` ; `ExprKind`/`StmtKind::Yield`.

## Hors-périmètre (→ 0.1%, `rust{}`)
- Coroutines à état arbitraire (`yield` entre logique impérative complexe, plusieurs points de reprise) →
  hors-périmètre v0 ou `rust{}` ; les `gen`-blocks nightly Rust non garantis.
- `yield from`, générateurs bidirectionnels (`send`).

## Comportement attendu
```
def evens(n: i64) -> iter[i64]:
    for i in range(n):
        if i % 2 == 0:
            yield i
for e in evens(10):
    print(e)
```
→ `(0..n).filter(|i| i % 2 == 0)` (désucrage en chaîne d'itérateurs) ; `for e in …`.

## Contrat / interface
`lex`/`parse` : `yield`. `ir.rs` : `StmtKind::Yield`. `infer` : fn à `yield` → `iter[T]` (≈ `impl Iterator`).
`lower` : reconnaître le motif `for … : (if …) yield e` → chaîne d'itérateurs ; sinon **erreur claire**
(« générateur trop complexe — utilise `rust{}` », honnête D5).

## Source maps
I8 : le `yield` et la chaîne d'itérateurs portent le `Span`.

## Critères d'acceptation
- Générateurs « boucle + condition + yield » → itérateur correct, consommé par `for` (test).
- Un générateur hors-périmètre → **erreur claire** orientant vers `rust{}` (pas un codegen faux).

## Décomposition
→ planif : syntaxe `yield`, IR, reconnaissance du motif boucle→itérateur, lowering, erreur hors-cas.

## Risques / questions ouvertes
- 🔶 **Le cas général est non couvert** et c'est assumé (D5/D6). Risque : la frontière « simple vs complexe »
  doit être **prévisible** (sinon DX frustrante). Documenter précisément les motifs supportés.
