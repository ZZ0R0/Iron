# [30700] `shared_sync[T]` → `Arc<Mutex<T>>` (partage mutable thread-safe)

- Version : V9 · Milestone : M9 · Statut : draft · Dépend de : 30300, 30400 · Invariants : I2, I3, I5

## Objectif
Donner à Iron un partage mutable **thread-safe**, prérequis du threading natif (70900). Le `shared[T]` de V6
(`Rc<RefCell<T>>`) est **mono-thread** (`Rc` est `!Send`) — `rustc` (filet I2) rejette son passage à un
thread. `shared_sync[T]` = `Arc<Mutex<T>>` : le **pendant `Send`/`Sync`** de `shared`.

## Périmètre
- **Type** : `shared_sync[T]` → `Arc<Mutex<T>>`. `Type::SharedSync(Box<Type>)` (gelé en fondation).
- **Constructeur** : `ref_sync(x)` (pendant de `ref(x)`) → `Arc::new(Mutex::new(x))`.
- **Accès** : lecture/écriture via `.lock()` (vs `.borrow()/.borrow_mut()` du `RefCell`) — la lower émet
  `.lock().unwrap()`. Clone = `Arc::clone` (partage du pointeur, cheap), jamais copie profonde (I5).
- **Verrou** : `with(s, f)` ou bloc — accès scoped au contenu (évite le double-lock → deadlock, footgun I5).

## Hors-périmètre
- Le `spawn`/`join` (70900). Les channels (`mpsc`) → via binding `std::sync::mpsc` ou `rust{}`.

## Comportement attendu
```
counter = ref_sync(0)        # Arc<Mutex<i64>>
# dans un thread (70900) :
with counter as c:           # c : &mut i64 (lock scoped)
    c = c + 1
```
→ `let counter = Arc::new(Mutex::new(0i64)); { let mut c = counter.lock().unwrap(); *c += 1; }`

## Contrat / interface
`ir.rs` : `Type::SharedSync`. `infer` : `ref_sync`→SharedSync, `with` lie le contenu verrouillé.
`lower` : `Arc<Mutex>`, `.lock().unwrap()`, `Arc::clone` au partage. `resolve` : `shared_sync` partagé
explicite (I3, jamais auto-cloné).

## Source maps
I8 : chaque `lock`/accès porte le `Span` Iron ; un poison/deadlock `rustc`/panic remonte au `Span`.

## Critères d'acceptation
- `ref_sync` + `with` compile, `Arc<Mutex>` émis, 0 `unsafe`.
- Passage à un `thread.spawn` (70900) : compile (Send OK) là où `shared` échouerait — test comparatif.
- Clone = `Arc::clone` (pas de copie profonde).

## Décomposition
→ planif : `Type::SharedSync` (fondation), `ref_sync`, accès `with`/`lock`, partage `Arc::clone`.

## Risques / questions ouvertes
- 🔶 Deadlock (double `lock`) = footgun runtime (comme le double-`borrow` du `RefCell`, spec V6). Documenter ;
  `with` scoped limite le risque.
- 🔶 `Mutex` empoisonné (panic d'un thread) → `.lock().unwrap()` re-panique. Acceptable au v0 (I2 filet).
