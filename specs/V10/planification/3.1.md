# [3.1] Defaulting + généralisation (let-polymorphism)

- Spec parente : 22100 · Version : V10 · Dépend de : 2.2 (unifié) · Statut : todo · **Vague 3** (parallèle)

## But
Clore l'inférence : (1) **defaulting** des vars numériques libres → `i64`/`f64` ; (2) **généralisation** des
`def f[T]` en schémas quantifiés instanciés à chaque appel. C'est ce qui fait que `pair_of[T](x)` type `x: T`
sans l'écrire et que les littéraux nus se résolvent.

## Fichiers touchés
`src/infer/engine/generalize.rs` (**possédé**, créé vide en 1.1). Lecture seule : `subst.rs`, `ir.rs`.

## Étapes
1. `default_unconstrained(subst)` : après point fixe, `Var` avec contrainte `Integral`/`Fractional` non
   résolue → `i64`/`f64`. **Après** tout le reste (sinon ré-introduit « str dans `+` → i64 »).
2. `generalize(fn, subst) -> Scheme` : lier les `Var` du corps au `T` **déclaré** de la signature (réutiliser
   le `T`, **pas** en créer un neuf — c'est le bug actuel de `pair_of[T](x)`).
3. `instantiate(scheme)` : `Var` fraîche par appel (let-polymorphism).
4. Ordre par **composantes fortement connexes** du graphe d'appels (récursion mutuelle).

## Critère de done
`pair_of[T](x)` (sans `x: T`) → `fn pair_of<T: Clone>(x: T) -> Vec<T>` ; littéraux nus défautent ; fns
mutuellement récursives non annotées typent (test SCC) ; **zéro `Var` résiduel** en sortie.
