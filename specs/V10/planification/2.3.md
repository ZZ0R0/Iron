# [2.3] Assomptions depuis les bindings + résolution de méthodes

- Spec parente : 22000 · Version : V10 · Dépend de : 1.1 · Statut : todo · **Vague 2** (parallèle)

## But
Brancher le moteur sur l'**auto-binding** (le couplage de la version) : les signatures des `.iri` deviennent
des **assomptions de typage**. Un appel de fonction/méthode bindée **contraint** les types Iron — c'est ce
qui fait disparaître l'annotation « param passé à une fonction externe ».

## Fichiers touchés
`src/infer/engine/assume.rs` (**possédé**, créé vide en 1.1). Lecture seule : `ir.rs` (`Bindings`),
`constraint.rs`.

## Étapes
1. `assumptions(bindings) -> Assumptions` : `extern fn` → (params, ret) ; `extern type` → type ; méthodes
   `(recv, nom) -> (params, ret)` (fusion `impl` Iron + `.iri`).
2. Instances de trait fournies par les bindings (un type externe satisfait `Display`/`Ord`… si son `.iri`/
   Rust le dit) → alimente la table de 2.2.
3. **Résolution de méthodes** (bidirectionnel) : `obj.m(args)` → unifier le receveur d'abord, puis chercher
   `m` dans les assomptions ; sinon **différer**.
4. Constructeurs : struct Iron `Contact(...)` + ctors externes `Buffer.new()`.

## Critère de done
`closest(query, names: list[str])` type **sans** annoter `query` (inféré `str` via `levenshtein(str,str)`) ;
chaîne de méthodes sur type bindé (`Regex.new(p).is_match(s)`) type sans annotation ; **testable** en
chargeant un `.iri` et en vérifiant la table d'assomptions.

## Notes

(génériques `AsRef`…) → opaque, annotation/`rust{}` (conforme « 0.1 % », pas une régression).
