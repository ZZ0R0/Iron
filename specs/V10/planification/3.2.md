# [3.2] Diagnostics de type Iron (mismatch → span)

- Spec parente : 22200 · Version : V10 · Dépend de : 2.2 (unifié) · Statut : todo · **Vague 3** (parallèle)

## But
Convertir les `TypeError` du solveur en **diagnostics Iron mappés sur le span** (« attendu `str`, trouvé
`i64` »), **avant** `rustc`. Iron diagnostique enfin ses types lui-même (I8/D8) ; la remontée rustc (60800)
reste le second rideau (D7/I2).

## Fichiers touchés
`src/infer/engine/diag.rs` (**possédé**, créé vide en 1.1). Lecture seule : `constraint.rs` (spans),
`ir.rs`. Réutilise `driver::line_col` (sans le modifier).

## Étapes
1. `TypeError -> CompileError` : message FR + **span primaire** (et secondaire pour le conflit), depuis les
   spans portés par les contraintes (1.1).
2. Catégories : mismatch d'unification · trait non satisfait · type ambigu · arité d'appel · champ/méthode
   inconnu.
3. Format : aligné sur la remontée rustc existante (`fichier:ligne:col: …`).

## Critère de done
≥ 1 programme mal typé par catégorie → message Iron **sur le bon span** ; aucun faux-positif sur le corpus
correct (50) + binding (30) ; **testable** en montant un `TypeError` et en vérifiant le span rendu.

## Notes
Parallèle à 3.1. Sur les contraintes de trait **différées**, garder le span de la **contrainte source** (pas
du point de détection) — sinon le message pointe loin du vrai coupable.
