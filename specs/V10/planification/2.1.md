# [2.1] Génération de contraintes (AST → contraintes)

- Spec parente : 21800 · Version : V10 · Dépend de : 1.1 · Statut : todo · **Vague 2** (parallèle)

## But
Parcourir l'AST et **émettre les contraintes** (mode *synth*) sans rien résoudre : chaque `NodeId` reçoit une
`Var` fraîche ou un type connu, et la liste de `Constraint` capture la sémantique (app, binaire, struct,
collections, flux I11, lambda).

## Fichiers touchés
`src/infer/engine/gen.rs` (**possédé**, créé vide en 1.1). Lecture seule : `constraint.rs`, `subst.rs`, `ir.rs`.

## Étapes
1. `generate(ast, assumptions, env) -> (Vec<Constraint>, TypeMap)` ; `Env` de portée (params/locaux/fns).
2. Littéraux (`Int → Var: Add`-friendly, `Str → str`, …), `Var` (lookup env), application `f(a,b)`.
3. Struct/enum (champs unifiés aux types déclarés), collections `[a,b]`/`xs[i]`/dict/set.
4. Binaires `a ⊕ b` → contrainte de trait (`typeof(a): Add`, `typeof(a)=typeof(b)`) — **interface** vers 2.2.
5. Flux I11 : `?`/`return None`/`raise` → contraintes `Result`/`Option` sur le retour de la fn courante.
6. Lambda `lambda x: e` → `fn(Var x) -> typeof(e)`.

## Critère de done
Sur des programmes jouets, le jeu de contraintes est correct (test : forme + nombre) ; tout `Expr`/`Stmt`
joignable a une entrée TypeMap ; chaque contrainte porte un span. **Testable sans solveur** (inspection).

## Notes

total + i` doit **unifier** (une seule var), pas créer deux locaux.
