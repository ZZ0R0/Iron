# [22000] Assomptions depuis les bindings + résolution de méthodes

- Version : V10 · Milestone : M10 · Statut : draft · Dépend de : 21800, 21900, 52100 · Invariants : I6, I7bis

## Objectif
Brancher le moteur sur l'**auto-binding** — le couplage que cette version rend explicite (D4). Les
signatures des `.iri` (`Bindings`) deviennent des **assomptions de typage** : appeler une fonction de crate
ou une méthode bindée **contraint** les types Iron environnants. C'est ce qui fait disparaître les
annotations « param passé à une fonction externe » et type les chaînes de méthodes sur objets bindés.

## Périmètre
- **Fns externes** : `levenshtein(a: str, b: str) -> usize` (du `.iri`) → contraintes sur les arguments à
  l'appel (`typeof(arg0) = str`, …) et sur le résultat. Idem `import std`.
- **Types externes & méthodes** : `Regex.new(...)`/`r.is_match(s)` → receveur typé `Regex`, méthode résolue
  via le `.iri` (params/retour). Instances de trait éventuelles fournies par le binding (22000 → 21900).
- **Résolution de méthodes** (bidirectionnel, D1) : `obj.m(args)` exige `typeof(obj)` connu → unifier d'abord
  le receveur, puis résoudre `m` dans les méthodes (Iron `impl` **ou** bindings) ; sinon contrainte différée.
- **Constructeurs** : `Contact(...)` (struct Iron) et ctors externes (`Buffer.new()`).

## Hors-périmètre
- La génération brute (21800) et l'unification (21900). Le defaulting (22100).

## Comportement attendu
```
import strsim
def closest(query, names: list[str]):
    return names[0]
    # levenshtein(query, n) : query unifié à str via la signature bindée ⇒ query: str, SANS annotation
```
→ `query` n'a plus besoin d'annotation : la signature `levenshtein(str,str)` la contraint.

## Contrat / interface
- `infer/engine/assume.rs` (nouveau) : charge `Bindings` → table d'`assumptions` (fn sig, méthode sig, type,
  instances de trait) consommée par 21800 (appels) et 21900 (instances).
- Méthodes : `(type_receveur, nom) → (params, ret)` — fusion `impl` Iron + bindings `.iri`.

## Critères d'acceptation
- `closest(query, names: list[str])` compile **sans** annoter `query` (inféré `str` via le binding).
- Une chaîne de méthodes sur un type bindé (`Regex.new(p).is_match(s)`) type sans annotation.
- La batterie-30 reste verte avec l'inférence pilotée par bindings (non-régression).

## Décomposition
→ planif : (1) ingestion des `extern fn` → assumptions ; (2) types + méthodes externes ; (3) résolution de
méthodes bidirectionnelle ; (4) instances de trait depuis bindings.

## Risques / questions ouvertes
- 🔶 Surcharge de méthodes (même nom, types receveurs différents) : résoudre par le type du receveur d'abord.
- 🔶 `.iri` produisant des types non mappables (génériques `AsRef`…) : restent opaques → annotation/`rust{}`
  (conforme au « 0.1 % »), pas une régression du moteur.
