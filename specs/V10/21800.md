# [21800] Génération de contraintes (AST → contraintes)

- Version : V10 · Milestone : M10 · Statut : draft · Dépend de : 21700 · Invariants : I9, I11

## Objectif
Parcourir l'AST et **émettre les contraintes** (21700) qui capturent la sémantique de typage de chaque
construction — sans rien résoudre. Sortie : une liste de `Constraint` + une `TypeMap` provisoire (chaque
`NodeId` → `Type::Var` fraîche ou type connu). C'est la passe *synth* du bidirectionnel (D1).

## Périmètre
- **Littéraux** : `Int → Var k` avec `k: Integral` (defaulting plus tard), `Str → str`, `Bool → bool`, etc.
- **Var** : type = celui lié dans l'environnement (param, local, fn).
- **Application** `f(a, b)` : `typeof(a) = param0(f)`, `typeof(b) = param1(f)`, `typeof(noeud) = ret(f)`.
- **Binaire** `a ⊕ b` : émet une **contrainte de trait** (`typeof(a): Add`, `typeof(a) = typeof(b)`,
  résultat selon l'op) — détail de résolution en 21900.
- **Struct/enum** : `Contact(name=…, age=…)` → champs unifiés aux types déclarés ; nœud = `Struct(Contact)`.
- **Collections** : `[a, b]` → `typeof(a) = typeof(b) = elem`, nœud = `list[elem]` ; `xs[i]` → `xs: list[E]`,
  nœud = `E` ; dict/set idem.
- **Flux Option/Result (I11)** : `?`, `return None`, `raise` → **ré-exprimés en contraintes** (la fn courante
  porte un `Var` de retour contraint `Option[_]`/`Result[_]`). Remplace `flow.rs` par des contraintes.
- **Lambda** : `lambda x: e` → `fn(Var x) -> typeof(e)`.

## Hors-périmètre
- Résolution/unification (21900). Bindings & méthodes (22000). Defaulting/généralisation (22100).

## Comportement attendu
```
def add(a, b):                # a: V0, b: V1
    return a + b              # V0: Add, V0 = V1, ret = V0
add(20, 22)                   # V0 = i64 (littéral), … ⇒ add: (i64,i64)->i64
```

## Contrat / interface
- `infer/engine/gen.rs` (nouveau) : `generate(ast, bindings, env) -> (Vec<Constraint>, TypeMap)`.
- Consomme l'`Env` (portée lexicale : params, locaux, fns). Produit des `Var` via `Subst::fresh`.

## Source maps
Chaque contrainte émise porte le `Span` du nœud d'origine (I8) — indispensable à 22200.

## Critères d'acceptation
- Sur un programme jouet, le jeu de contraintes généré est correct (test : nombre + forme des contraintes).
- Tout `Expr`/`Stmt` joignable reçoit une entrée `TypeMap` (var ou type concret).
- I11 : un programme à `?`/`None`/`raise` génère les contraintes `Result`/`Option` attendues.

## Décomposition
→ planif : (1) littéraux/var/app ; (2) struct/enum/collections/index ; (3) binaires → contraintes de trait
(interface avec 21900) ; (4) flux I11 → contraintes ; (5) lambda.

## Risques / questions ouvertes
- 🔶 Portée et *shadowing* (réassignation `x = …`) : l'`Env` doit modéliser correctement les locaux ; le
  pattern accumulateur (`total = 0; total = total + i`) doit unifier, pas créer deux vars.
