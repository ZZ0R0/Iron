# [21700] Socle : variables de type, substitution, langage de contraintes

- Version : V10 · Milestone : M10 · Statut : draft · Dépend de : 20100 · Invariants : I6, I9

## Objectif
Poser le **contrat figé** sur lequel tout le moteur s'appuie (D1, D2) : la représentation d'une **variable
de type**, la **substitution** (union-find) qui la résout, et le **langage de contraintes** échangé entre la
génération (21800) et le solveur (21900). C'est la fondation : tant qu'elle n'est pas gelée, le fan-out est
impossible.

## Périmètre
- **`Type::Var(TyVar)`** : nouvelle variante de l'IR `Type` (métavariable d'inférence). `TyVar` = `u32` dense.
- **`Subst`** : structure union-find `TyVar → Type` (avec compression de chemin), + `apply(subst, ty)`.
- **`Constraint`** : l'énumération échangée. Au minimum :
  - `Eq(Type, Type)` (égalité à unifier),
  - `Trait(Type, TraitBound)` (contrainte de classe, ex. `T: Add` — détail en 21900),
  - chaque contrainte porte un `Span` (origine, pour I8/D8).
- **`TraitBound`** : ensemble béni (`Add`, `Sub`, `Mul`, `Div`, `Ord`, `Eq`, `Display`…), mappé 1:1 Rust.

## Hors-périmètre
- La **génération** des contraintes (21800), leur **résolution** (21900), le **defaulting** (22100).
- Toute logique métier : ce module ne fait que *représenter* et *substituer*.

## Comportement attendu
```
TyVar(0), TyVar(1)…              # fraîches, allouées par un compteur
Subst { 0 → Str, 1 → Var(0) }   # apply(Var(1)) = Str (compression)
Constraint::Eq(Var(0), Str)     # « Var(0) doit être str », span = …
```
À la fin de l'inférence, `apply(subst, …)` sur tout nœud ne doit **jamais** laisser de `Var` (invariant D2 ;
sinon defaulting 22100 ou erreur 22200).

## Contrat / interface
- `ir.rs` : `Type::Var(u32)`. **Aucun autre composant ne doit voir une `Var`** (lower/resolve reçoivent des
  types résolus) — garde-fou à tester.
- `infer/engine/subst.rs` (nouveau) : `Subst`, `fresh() -> TyVar`, `union`, `apply`, `occurs_check`.
- `infer/engine/constraint.rs` (nouveau) : `Constraint`, `TraitBound`.

## Source maps
N/A pour la représentation ; **mais** chaque `Constraint` porte un `Span` → c'est ce qui permettra à 22200
de remonter une erreur sur la ligne Iron (I8). Contrat : ne jamais créer de contrainte sans span d'origine.

## Critères d'acceptation
- `Type::Var` ajouté ; `apply`/`union`/`occurs_check` testés unitairement (substitution transitive, cycles
  rejetés par occurs-check).
- Un programme qui compile aujourd'hui compile encore (la variante est inerte tant que rien ne l'émet).
- `lower`/`resolve` reçoivent **zéro `Var`** (assertion de garde en debug).

## Décomposition
→ planif : (1) variante IR + propagation des `match Type` exhaustifs ; (2) `Subst` union-find + tests ;
(3) `Constraint`/`TraitBound` + spans.

## Risques / questions ouvertes
- 🔶 Ajouter une variante à `Type` touche **tous** les `match Type` du projet (lower, lsp, iri…). Mécanique
  mais large → repérer via le compilateur (matchs non exhaustifs) et router vers `unreachable!`/résolu.
