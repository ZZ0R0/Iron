# [70200] Modules multi-fichiers Iron (`import`)

- Version : V6 · Milestone : M6+ · Statut : draft · Dépend de : 70100, 10200 · Invariants : I9, I6

## Objectif
Plusieurs fichiers `.irn` formant un programme : `import` de modules Iron (distinct de `use "x.iri"` qui
importe des bindings Rust).

## Périmètre
- `import foo` charge `foo.irn` → ses items (`fn`/`struct`/`enum`/`trait`) deviennent accessibles.
- Résolution des chemins (relatifs au fichier courant) ; mono-binaire en sortie (tous les modules → un `main.rs`).

## Hors-périmètre
Visibilité fine (`pub`/privé) ; packages versionnés ; compilation séparée.

## Comportement attendu
- `import math` + `math.area(...)` (ou `area(...)` si non ambigu) → items de `math.irn` lowerés dans le crate.

## Contrat / interface
Le driver lit le graphe d'imports, fusionne les `Ast` (préfixage/namespacing à figer), lowering unifié.
Détection de **cycles** d'import.

## Source maps
Multi-`FileId` : chaque module a son `FileId` ; remontée pointe le bon fichier (I8).

## Critères d'acceptation
Programme sur 2 fichiers (un module + `main`) → compile + exécute ; cycle d'import → erreur claire.

## Décomposition
→ planif.

## Risques / questions ouvertes
- ❓ Namespacing : `module.item` explicite vs import à plat. À trancher.
