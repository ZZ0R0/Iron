# [20400] Inférence Option/Result depuis le flux + `try/except`

- Version : V6 · Milestone : M5+ · Statut : draft · Dépend de : 20200 · Invariants : I11, I12, I13

## Objectif
Honorer **I11** réellement : déduire `Option<T>`/`Result<T, IronError>` du **flux de contrôle**, sans
annotation ni constructeurs explicites. Et `try/except` comme **sucre** abaissé vers `match`.

## Périmètre
- Analyse **« definitely-returns »** (toutes branches/bras retournent ?) pour distinguer chute (→ `Option`).
- Fn qui **chute** + a un `return <valeur>` → `Option<T>` (`return v` → `Some(v)`, chute → `None`).
- Fn utilisant `?` ou op faillible → `Result<T, IronError>`.
- `try: … except e: …` → `match` sur le `Result`.

## Hors-périmètre
Inférence d'un `E` précis (post-1.0, I13). Coexistence avec l'annotation actuelle (qui reste valide).

## Comportement attendu (Iron → Rust)
- `fn find(xs, t):  for x in xs:  if x==t: return x` (chute) → `-> Option<T>`, `return Some(x)`, fin `None`.
- `fn read() -> i64:  v = parse()?  return v` → `-> Result<i64, IronError>`.
- L'analyse **doit** classer `match` exhaustif tous-bras-`return` comme *definitely-returns* (sinon
  régression : `classify` deviendrait `Option` à tort).

## Contrat / interface
`flow.rs` calcule le **type de retour effectif** par fn → stocké (TypeMap[fn.id]) ; `lower` l'émet en
signature + enveloppe les `return` (`Some`/`Ok`) + ajoute `None` à la chute. `sigs` mis à jour pour les appels.

fn à chute + valeur → `Option` exécutable ; `?` → `Result` ; `try/except` → `match` ; **corpus V0–V5 inchangé**
(aucune fn mal reclassée).
