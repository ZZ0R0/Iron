# [30300] Partage explicite `ref`/`Rc` + `Weak` + warning aliasing

- Version : V6 · Milestone : M2++ · Statut : draft · Dépend de : 30100, 30200 · Invariants : I5, I3, I2

## Objectif
Honorer **I5** (partage explicite via `Rc`/`Arc`, équiv. `ref` Nim ; `Weak` à la charge utilisateur) et le
**warning d'I3** (« tu voulais peut-être partager ») quand un auto-clone changerait une sémantique de partage.

## Périmètre
- Type/qualificatif **`ref T`** → `Rc<RefCell<T>>` (partage mutable) ou `Rc<T>` (partage immuable).
- Construction `ref(x)`, accès partagé, `weak(r)` → `Weak`.
- **Warning I3** : détecter un aliasing mutable résolu par auto-clone → lint *perf/correction* (`--audit`).

## Hors-périmètre
Ramasse-cycles (I5 : `Weak` explicite, documenté). Inférence automatique du partage.

## Comportement attendu (Iron → Rust)
- `r = ref(node)` → `Rc<RefCell<Node>>` ; `r.val` lit/écrit via `borrow()`/`borrow_mut()`.
- `w = weak(r)` → `Rc::downgrade(&r)`.
- Aliasing mutable non explicite → warning (pas une erreur, I4).

## Contrat / interface
Nouveau `Type::Shared(Box<Type>)` (Rc) ; lowering via `Rc`/`RefCell`/`Weak`. **Zéro `unsafe`** (I2).

## Source maps
N/A. Le warning aliasing porte le `Span` Iron.

## Critères d'acceptation
Un graphe partagé (≥2 propriétaires d'un même nœud) construit + muté via `ref` → compile + exécute ;
`weak` casse un cycle ; warning aliasing émis sur le cas piège.

## Décomposition
→ planif. Structurant (toucher l'ownership). 

## Risques / questions ouvertes
- 🔶 Ergonomie `Rc<RefCell>` (emprunts dynamiques `borrow()` → panics runtime possibles). À cadrer.
- 🔶 `Weak`/cycles : documentés, à la charge utilisateur (I5).
