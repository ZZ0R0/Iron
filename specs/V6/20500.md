# [20500] Inférence des types de paramètres

- Version : V6 · Milestone : M1+ · Statut : draft · Dépend de : 20100 · Invariants : I6, I2

## Objectif
Lever la dette 20100 : ne plus exiger l'annotation de **type de paramètre** quand il est déductible.

## Périmètre
- Inférence d'un type de param à partir de son usage **local** (ops, accès champ, appels) et/ou des
  **sites d'appel** (types des arguments).
- Repli : si indéterminé → **générique implicite** (`fn f(x)` → `fn f[T](x: T)`), rustc tranche (I2).

## Hors-périmètre
Inférence globale inter-fonctions complète (Hindley-Milner) ; on reste **léger + rustc filet**.

## Comportement attendu (Iron → Rust)
- `fn double(x): return x + x` → `x` déduit numérique → `fn double(x: i64) -> i64` (ou générique si ambigu).
- `fn area(p): return p.x * p.x` → `p` a un champ `x` → type struct déductible, sinon générique borné.

## Contrat / interface
Passe d'inférence locale (+ sites d'appel) ; les params non résolus deviennent des **génériques implicites**
(réutilise 20300/`[T]`). Annotation explicite prime.

## Source maps
N/A. Conflit de type → `Span` Iron (rustc remonté).

## Critères d'acceptation
Programmes du corpus sans annotation de param (là où déductible) → compilent à l'identique.

## Décomposition
→ planif.

## Risques / questions ouvertes
- 🔶 Ambiguïté numérique (`i64` vs `f64`) → générique ou défaut `i64` ? À trancher.
