# [50400] Interop élargi : `bind` complet, `rust:` étendu, types `Extern`

- Version : V6 · Milestone : M4+ · Statut : draft · Dépend de : 50100, 50200, 50300 · Invariants : I7, I6

## Objectif
Compléter l'interop (V2) : couverture de `ironc bind`, forme indentée de `rust:`, et exercer réellement
les types opaques `Extern`.

## Périmètre
- **`bind`** : mapper plus que `i64/f64/bool` — `str`/`String`, collections, structs publics ; **chemins en
  sous-module** (`crate::mod::fn`) ; tolérer plusieurs **versions** de rustdoc-json (≥ v57).
- **`rust:`** : forme **indentée** `rust:` (pas seulement `rust { }`) ; capture sautant `/* */` et `'{'`.
- **`Extern`** : test e2e d'un **type opaque** (`extern type Inst = "std::time::Instant"`) manipulé via ses fns.

## Hors-périmètre
Génériques dans les bindings ; macros Rust.

## Comportement attendu
- `bind` produit des `extern fn` à signatures `str`/struct corrects, chemins de sous-module exacts, items
  non mappables toujours **sautés et comptés**.
- `rust:` indenté = équivalent `rust { }`.
- Un `extern type` opaque passé/retourné via bindings → compile + exécute.

## Contrat / interface
Étendre `bind::map_type` (plus de types), résolution de chemin via `.paths` rustdoc ; lexer : capture
`rust:` indentée ; `iri`/`infer`/`lower` : `Extern` de bout en bout.

## Source maps
Erreur dans un `rust:` indenté → `Span` du bloc (I8).

## Critères d'acceptation
`bind` d'une crate à API `str`/struct → `.iri` utilisable ; `rust:` indenté compile ; type opaque e2e.

## Décomposition
→ planif.

## Risques / questions ouvertes
- 🔶 Format rustdoc-json **instable** entre versions — cibler + dégrader proprement.
