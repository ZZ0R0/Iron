# [60200] Source maps — granularité expression

- Version : V6 · Milestone : M3+ · Statut : draft · Dépend de : 60100, 40100 · Invariants : I8, I2

## Objectif
Atteindre la **cible d'I8** annoncée dès V0 : mapping `Span` Iron ↔ Rust à la granularité **expression**
(V0–V5 = granularité **instruction**).

## Périmètre
- Émettre un marqueur par **expression** (pas seulement par instruction), survivant à `prettyplease`.
- Remonter une erreur `rustc` au **sous-bout** exact (pas juste la ligne).
- Systématiser la **section « Source maps »** dans chaque spec codegen (obligation I8).

## Hors-périmètre
Débogueur pas-à-pas ; DWARF.

## Comportement attendu
- Erreur de type sur `a + b` dans `x = f(a) + g(b)` → pointe `a + b` (ou l'opérande fautif), pas la ligne entière.

## Contrat / interface
`lower` : marqueurs au niveau `Expr` (densité accrue) ; `sourcemap` : ré-localisation fine post-format.
Maîtriser la **pollution** de marqueurs (les retirer du binaire final ou marqueurs « invisibles »).

## Source maps
**C'est** la spec source-maps (raffinement de 60100).

## Critères d'acceptation
Une erreur `rustc` forcée sur une sous-expression → message pointant le **sous-bout** Iron ; robustesse au
reformatage conservée.

## Décomposition
→ planif.

## Risques / questions ouvertes
- 🔶 Trop de marqueurs ⇒ `prettyplease` peut les déplacer/fusionner. Mécanisme « invisible » (`#[line]`-like) à étudier.
