# [20600] Motifs `match` avancés : gardes, champs nommés, imbrication

- Version : V6 · Milestone : M5+ · Statut : draft · Dépend de : 20300 · Invariants : I6

## Objectif
Compléter les motifs de `match` (V3 = variante tuple / `_` / variable / littéral) : **gardes**, variantes à
**champs nommés**, motifs **imbriqués**.

## Périmètre
- **Gardes** : `Some(x) if x > 0:` → `Some(x) if x > 0 => …`.
- **Champs nommés** : `enum E: V(a: i64, b: str)` + motif `E.V(a, b)` (positionnel) ou `E.V(a=pa, b=pb)`.
- **Imbrication** : `Some(Point(x, y)):` → `Some(Point(x, y)) => …`.

## Hors-périmètre
Or-patterns `A | B` ; ranges `1..5` (ultérieur).

## Comportement attendu (Iron → Rust)
- `match o:  Some(x) if x > 0:  …` → `Some(x) if x > 0 => { … }`.
- variante à champs nommés → `enum E { V { a: i64, b: String } }` + motif `E::V { a, b }`.

## Contrat / interface
Étendre `Pattern` (garde `Option<Expr>`, sous-motifs nommés) et `ItemKind::Enum` (variantes à champs
nommés). Lowering → motifs Rust correspondants ; exhaustivité → rustc (I8/I2).

## Source maps
Garde fausse / motif non exhaustif → `Span` Iron (rustc remonté).

## Critères d'acceptation
`match` avec garde + variante à champs nommés + motif imbriqué → compile + exécute.

## Décomposition
→ planif.

## Risques / questions ouvertes
- ❓ Liaison des champs nommés : positionnelle vs `champ=motif`. À figer.
