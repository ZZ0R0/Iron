# [10300] Parser : comparaison chaînée `a < b < c`

- Version : V6 · Milestone : M0+ · Statut : draft · Dépend de : 10200 · Invariants : I9

## Objectif
Supporter la **comparaison chaînée** façon Python : `a < b < c` ≡ `a < b and b < c` (aujourd'hui parsée
`(a < b) < c` → `bool < i64`, erreur).

## Périmètre
- Détecter une chaîne d'opérateurs de comparaison et l'abaisser en conjonction `and`.
- Évaluation **unique** des opérandes intermédiaires (sémantique Python : `b` évalué une fois).

## Hors-périmètre
Chaînage d'autres opérateurs.

## Comportement attendu (Iron → Rust)
- `1 < x < 10` → `(1 < x) && (x < 10)` (avec `x` évalué une fois si effet de bord — via `let` temporaire).

## Contrat / interface
`parse.rs` : dans `cmp_expr`, collecter `op0 a op1 b op2 c …` et produire l'AST conjonctif. Lowering inchangé.

## Source maps
Spans préservés sur chaque comparaison.

## Critères d'acceptation
`if 1 < x < 10:` compile + exécute (vrai pour `x` dans l'intervalle).

## Décomposition
→ planif.

## Risques / questions ouvertes
- ❓ Opérande intermédiaire à effet de bord : `let` temporaire pour évaluation unique. À figer.
