# [51500] Namespacing : `extern mod` & chemins de module

- Version : V8 · Milestone : M8 · Statut : draft · Dépend de : 50900, 51000, 51100 · Invariants : I6, I7

## Objectif
Donner un **espace de noms** aux items bindés, comme les modules Python (`regex.escape(...)`,
`json.parse(...)`). Sans ça, tous les `extern fn` d'un crate atterrissent à plat dans l'espace global et
collisionnent (deux crates avec `new`, `parse`…). Cette spec groupe les items sous un nom de module qui
devient le **préfixe d'appel** Iron, mappé au **chemin Rust** correspondant.

## Périmètre
- **Grammaire** (réservée en 50900) : `extern mod <name>:` + bloc indenté d'items (fns/types) appartenant au module.
- **Émission `bind`** : grouper les items par leur **chemin de sous-module** rustdoc (`crate::a::b::fn` →
  module `b`). Profondeur configurable (défaut : dernier segment de module).
- **Côté Iron** (consommé par 21100/40200) : `mymod.f(x)` résout vers l'`ExternFn` du module `mymod`, dont
  `rust_target` porte le chemin complet.
- Cohabitation avec l'`import` Iron (70200) : un `extern mod` est un module **externe** ; même surface
  d'appel `mod.f(...)` que les modules Iron natifs.

## Hors-périmètre
- Le chargement multi-fichiers Iron (`import`) → 70200 (existant).
- L'inférence/lowering de l'appel `mod.f(...)` → 21100/40200.

## Comportement attendu
```
crate regex = "1.11"
extern mod regex:
    extern fn escape(s: str) -> str = "regex::escape"
    extern type Regex = "regex::Regex": …
```
Côté Iron :
```
use "regex.iri"
s = regex.escape("a.b")        # → regex::escape(&s)
r = regex.Regex.new("a+")      # type namespacé
```

## Contrat / interface
`bind/modules.rs` : `pub fn group_modules(b: &mut Bindings)` — peuple `b.mods: Vec<ExternMod>` et préfixe la
résolution. `Bindings` expose `resolve(path: &[&str]) -> Option<&ExternFn>` pour que `infer`/`lower`
résolvent `regex.escape` → l'`ExternFn`.

## Source maps
N/A au binding ; l'appel `mod.f` reçoit son `Span` en 40200.

## Critères d'acceptation
- `bind regex` produit un `extern mod regex` ; `regex.escape("a.b")` compile et s'exécute.
- Deux crates avec un `parse` homonyme, importés ensemble → pas de collision (`a.parse` ≠ `b.parse`).
- Un type namespacé (`regex.Regex`) est constructible (`regex.Regex.new(...)`).

## Décomposition
→ planif `2.5` : groupement par sous-module + `resolve` + cohabitation `import`.

## Risques / questions ouvertes
- 🔶 Profondeur de namespacing (crate entier sous 1 module vs sous-modules imbriqués) : défaut = nom du crate
  comme module racine + sous-modules à plat. Affinable.
- 🔶 Conflit `extern mod` vs module Iron natif de même nom → erreur claire (espaces de noms disjoints requis).
