# [51400] Instance-pinning : monomorphisation d'un générique à la demande

- Version : V8 · Milestone : M8 · Statut : draft · Dépend de : 50900, 51000 · Invariants : I6, I7

## Objectif
Récupérer la **couche assistée B** (mesurée : +10–20 pts de couverture). Les fns/méthodes **génériques**
(`fn from_str<T: DeserializeOwned>(s: &str) -> Result<T>`) ne s'auto-bindent pas (type de retour inconnu).
Mais un humain peut **épingler une instance concrète** en **1 ligne** — exactement comme Nim binde les
templates C++. Cette spec donne le mécanisme : un chemin Rust monomorphisé devient un binding mappable.

## Périmètre
- **Directive `bind`** : `ironc bind <crate> --instantiate "<path>::<<TypeArgs>> as <iron_name>(<sig>)"`.
  Ex. `--instantiate "serde_json::from_str::<Point> as parse_point(s: str) -> Result[Point]"`.
- **`.iri` curé** : autoriser un `extern fn` dont le `rust_target` porte des **arguments de type explicites** :
  `extern fn parse_point(s: str) -> Result[Point] = "serde_json::from_str::<Point>"`.
- Validation : les `TypeArgs` doivent être des types **déjà bindés** (réf externe connue ou scalaire) ; sinon
  erreur claire.

## Hors-périmètre
- L'**inférence** des bornes de traits (vérifier que `Point: DeserializeOwned`) → laissée à `rustc` (I2,
  filet). Si la borne n'est pas satisfaite → erreur `rustc` remontée I8, pas un binding faux silencieux.
- Auto-deviner les instances utiles → non (c'est *assisté*, D5).

## Comportement attendu
```
extern fn parse_point(s: str) -> Result[Point] = "serde_json::from_str::<Point>"
```
Côté Iron : `p = parse_point(text)?` → lower émet `serde_json::from_str::<Point>(&text)`. `rustc` vérifie la
borne. Une 2ᵉ instance (`parse_line`) = une 2ᵉ ligne.

## Contrat / interface
`bind/instantiate.rs` : `pub fn parse_instantiation(spec: &str) -> CResult<ExternFn>` (depuis `--instantiate`)
et extension du parseur `.iri` (50900) pour accepter `::<…>` dans `rust_target`. Le `rust_target` est passé
**verbatim** à la lower (40200), qui émet le chemin tel quel.

## Source maps
N/A au binding ; l'appel monomorphisé reçoit le `Span` de l'appel Iron en 40200.

## Critères d'acceptation
- `--instantiate "serde_json::from_str::<i64> as parse_int(s: str) -> Result[i64]"` → `.iri` valide,
  `parse_int("42")` compile et renvoie `42`.
- Type-arg inconnu (`::<Inexistant>`) → erreur de binding claire (pas de `.iri` cassé).
- Une instance dont la borne n'est pas satisfaite → erreur `rustc` remontée en `Span` Iron (I8), pas un crash.

## Décomposition
→ planif `2.4` : parseur `--instantiate` + `::<…>` dans `rust_target` + validation des type-args.

## Risques / questions ouvertes
- 🔶 Syntaxe de la directive : la mini-DSL `"path::<T> as name(sig)"` est-elle assez claire ? Alternative :
  un `.iri` curé écrit à la main (toujours possible). **Décision** : les deux ; `--instantiate` = sucre.
- 🔶 Plusieurs type-args (`HashMap::<String,i64>::new`) → supportés (liste), testés.
