# [21100] Inférence des appels, méthodes & types externes

- Version : V8 · Milestone : M8 · Statut : draft · Dépend de : 50900, 51000, 51100, 51500 · Invariants : I6, I11, I13

## Objectif
Rendre le `.iri` v2 **visible au système de types**. Pour qu'un programme Iron utilisant un crate bindé
type-checke, l'inférence doit connaître : le type-handle d'un `extern type`, le type de retour d'une méthode
(`r.is_match(t)` → `bool`), d'un constructeur (`Regex.new(p)` → `Result[Regex]`), d'un appel namespacé
(`regex.escape(s)` → `str`), et d'une instance monomorphisée (51400). C'est le pendant « infer » de la
fondation : minimal au squelette (1.3), complet ici.

## Périmètre
`infer` (consomme `Bindings` via `load_bindings`) :
- Enregistrer chaque `ExternType.iron_name` comme `Type::Extern(name)` connu.
- Résoudre `obj.method(args)` quand `typeof(obj) = Type::Extern(T)` : chercher `method` dans `types[T].methods`
  → type de retour = `ExternFn.ret`.
- Résoudre `T.ctor(args)` / `mod.fn(args)` (namespacing 51500) via `Bindings::resolve`.
- Vérifier l'arité et (au mieux) les types des arguments ; mismatch → erreur Iron (Span), pas attendre `rustc`.
- `Result[T]`/`Option[T]` de retour → s'intègrent au flux `?`/`try` existant (I11, I13).

## Hors-périmètre
- L'**émission** Rust de l'appel + glue idiomes → 40200.
- L'inférence des bornes de traits d'une instance (51400) → `rustc` (I2).

## Comportement attendu
```
use "regex.iri"
r = regex.Regex.new("a+")     # infer: r : Result[Regex]
ok = r?.is_match("aaa")       # infer: is_match → bool ; ? déplie Result (I11)
```
Erreur attendue si `r.is_match(123)` (arg `i64` au lieu de `str`) → diagnostic Iron au `Span` de l'appel.

## Contrat / interface
`infer` : la `TypeMap` associe les `NodeId` des appels externes à leur `Type`. `Type::Extern(String)` ajouté
au besoin (cf. D2 ; coordonné avec la fondation IR 50900). `Bindings::resolve` (51500) est l'unique point
d'entrée de résolution des chemins.

## Source maps
N/A (inférence ne génère pas de Rust ; elle annote des `NodeId`). Les erreurs de type portent un `Span` Iron (I8/60400).

## Critères d'acceptation
- Programme Iron utilisant `regex` (ctor + méthode + namespacing) type-checke sans erreur.
- `r.is_match(123)` → erreur de type Iron claire (pas une erreur `rustc` obscure).
- Retour `Result[Regex]` correctement déplié par `?`/`try` (test flux).

## Décomposition
→ planif `1.3` (minimal : 1 type + 1 méthode) puis `3.1` (complet : ctors, namespacing, instances, vérif args).

## Risques / questions ouvertes
- 🔶 Méthode introuvable sur un `Type::Extern` (typo ou méthode non bindée car sautée) → message qui **liste les
  méthodes disponibles** + signale si elle a été sautée au binding (DX honnête).
- 🔶 Surcharge de noms entre méthode bindée et builtin Iron → la méthode externe prime sur le handle externe.
