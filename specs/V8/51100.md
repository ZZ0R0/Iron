# [51100] Extraction POO : méthodes & constructeurs depuis les `impl`

- Version : V8 · Milestone : M8 · Statut : draft · Dépend de : 50900, 51000 · Invariants : I6, I7

## Objectif
Capturer **la POO des crates** — là où est ~99 % de la valeur mesurée. Le binder actuel ne regarde que les
`inner.function` de premier niveau et **ignore toutes les méthodes** (qui vivent dans les `impl`). Cette spec
parcourt les `impl` **inhérents** d'un type public et en extrait les **méthodes** (1ᵉʳ param `self`) et les
**constructeurs** (fns associées sans `self`), pour peupler l'API du type externe.

## Périmètre
`bind/methods.rs` :
- Parcourir `index` pour les items `inner.impl` **inhérents** (`trait == null`), non synthétiques, non blanket,
  dont le `for` est un type **public** du crate.
- Pour chaque item de `impl.items` qui est une `function` publique :
  - `self`/`&self`/`&mut self` en 1ᵉʳ param → **méthode**, `recv = ByValue|ByRef|ByRefMut`.
  - sinon → **constructeur** / fn associée (`recv = None`).
- Projeter la signature via `map_type` (51000) ; non mappable → sauté + compté.
- Rattacher au `ExternType` correspondant (`ctors` / `methods`).

## Hors-périmètre
- Émettre la **déclaration** du `extern type` lui-même + fermer le graphe → 51200.
- Méthodes de **traits** (`impl Trait for T`) → hors V8 (D6 ; stretch protocoles V9).
- Idiomes (builder/getter…) → 51300 (ici on extrait la signature brute ; le tag vient après).

## Comportement attendu
```rust
impl Regex {
    pub fn new(re: &str) -> Result<Regex, Error> { … }   // ctor
    pub fn is_match(&self, text: &str) -> bool { … }     // méthode &self
}
```
→
```
extern type Regex = "regex::Regex":
    fn new(re: str) -> Result[Regex]      = "regex::Regex::new"
    fn is_match(self, text: str) -> bool  = "is_match"
```
Côté Iron : `r = Regex.new("a+"); r.is_match("aaa")` (style Python).

## Contrat / interface
`bind/methods.rs` : `pub fn extract_impls(rustdoc: &Value, types: &mut Vec<ExternType>)` — remplit `ctors`/
`methods` des `ExternType` déjà connus (créés par 51200) ou crée l'entrée à la volée. `rust_target` d'une
méthode = nom court (résolu contre `rust_path` du type par 40200) ; d'un ctor = chemin complet.

## Critères d'acceptation
- `bind regex` : `Regex` porte `is_match`, `find`, `captures`, … (méthodes réellement extraites, comptées).
- Un ctor (`new`, `with_capacity`) est distingué d'une méthode (`recv = None`).
- `&self` vs `&mut self` vs `self` → `recv` correct (testé).

## Décomposition
→ planif `2.1` : parcours des `impl` inhérents, distinction méthode/ctor, `recv`, rattachement aux types.

## Risques / questions ouvertes
- 🔶 Plusieurs `impl` pour un même type (impl conditionnels) → fusionner les méthodes ; collisions de noms
  (rares) → garder la 1ʳᵉ + compter. Documenté.
- 🔶 Méthodes génériques sur la méthode elle-même (`fn parse<T>(&self)`) → sautées (couche B / 51400).
