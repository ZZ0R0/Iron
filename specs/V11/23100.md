# [23100] Diagnostics de type Iron riches

- Version : V11 · Milestone : M11 · Statut : draft · Dépend de : 22200, 23000 · Invariants : I2, I8

## Objectif
Étendre les diagnostics natifs (D8/DA-3) au-delà des conflits de primitives : Iron signale **plus** d'erreurs
de type lui-même, sur la ligne Iron, **avant** `rustc` (qui reste le filet, I2). Confort dev (le checker
VSCode en bénéficie directement, `ironc check`).

## Périmètre
Catégories ajoutées (toutes sur un type **connu**, sinon `rustc` filet) :
- **champ inconnu** : `p.foo` où `p: Point` n'a pas de champ `foo` → « `Point` n'a pas de champ `foo` ».
- **méthode inconnue** sur un type connu (struct/enum/externe bindé).
- **arité d'appel** : nombre d'arguments ≠ nombre de params d'une fonction connue.
- **borne de trait non satisfaite** quand le moteur peut la trancher (`display(x)` avec `x` sans le trait).

## Hors-périmètre
- Tout ce que le moteur ne peut pas trancher avec certitude → **`rustc` filet** (zéro faux-positif, priorité).

## Comportement attendu
```
def f(p): return p.foo       # si p: Point connu, et pas de champ foo
→ ironc: erreur: type : `Point` n'a pas de champ `foo`   (avant rustc)
```

## Contrat / interface
`infer/engine/diag.rs` + `check_types` : nouvelles catégories d'erreur, message FR + span Iron. Conservateur
(comme V10) : **zéro faux-positif** sur corpus+binding.

## Source maps
**Cœur** : chaque diagnostic pointe la ligne Iron d'origine (I8).

## Critères d'acceptation
- ≥ 1 fixture négative par catégorie → message Iron natif sur le bon span.
- **Zéro faux-positif** : corpus 50 + binding 30 + zero-annot toujours verts.

## Décomposition
→ planif : (1) champ/méthode inconnus ; (2) arité ; (3) borne de trait ; (4) corpus de tests négatifs.

## Risques / questions ouvertes
- 🔶 Ne signaler que sur un type **résolu concret** (sinon faux-positif sur un générique/var) — règle stricte.
