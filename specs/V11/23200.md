# [23200] Flux Option/Result en contraintes + retrait `flow.rs` + couverture `local`

- Version : V11 · Milestone : M11 · Statut : draft · Dépend de : 21800 · Invariants : I9, I11

## Objectif
Finir l'unification du système de types : l'inférence Option/Result **par flux** (I11), aujourd'hui dans
`flow.rs`, devient des **contraintes** du moteur → `flow.rs` **retiré**. Et **mesurer** la couverture du
moteur vs `local.rs` (objectif retrait, DA-5), sans casser les 80 verts.

## Périmètre
- **DA-4** : porter `effective_ret`/`definitely_returns`/`has_value_return` en **contraintes** générées par
  `gen` : chute (pas de `return` sur tous les chemins + un `return v`) → `Option[T]` ; `?` dans le corps →
  `Result[T]`. `lower` compare déclaré vs effectif via la `TypeMap` (inchangé). Retrait de `flow.rs`.
- **DA-5** : audit de **couverture** — % de nœuds dont le type vient du **moteur** (vs repli `local.rs`).
  `local.rs` conservé **uniquement** en repli des nœuds non couverts. Retrait total si couverture 100 % sur
  corpus+binding ; sinon **mesurer + documenter** le reliquat (honnêteté, pas de retrait à l'aveugle).

## Hors-périmètre
- Réécrire tout `local.rs` d'un coup (risque 80 verts) — on **mesure** et on retire ce qui est prouvé couvert.

## Comportement attendu
`def first(xs): if len(xs) > 0: return xs[0]` (chute) → `Option[T]` inféré **par contrainte** (plus par
`flow.rs`). Programmes à `?`/`None`/`raise` du corpus : verts **par le moteur**.

## Contrat / interface
`infer/engine/gen.rs` : contraintes de flux (Option/Result). `infer/mod.rs` : retrait de `flow`. Audit :
compteur « nœuds typés moteur / total ».
