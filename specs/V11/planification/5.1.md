# [5.1] Surcharge d'opérateurs (`__dunder__` → `std::ops`)

- Spec parente : 23500 · Version : V11 · Dépend de : 4.1 · Statut : todo · **Vague 5**

## But
Opérateurs surchargeables sur types user via méthodes spéciales, désucrées en `impl std::ops`.

## Fichiers touchés
`src/lower.rs` (dunder reconnu dans une classe → `impl <Trait> for <Type>`) · `infer/engine/gen.rs` (`a ⊕ b`
sur type user → contrainte satisfaite, résultat = retour du dunder).

## Étapes
1. Table **bénie** dunder→trait : `__add__`→`Add`, `__sub__`→`Sub`, `__mul__`→`Mul`, `__div__`→`Div`,
   `__eq__`→`PartialEq`, `__lt__`→`PartialOrd`, `__str__`→`Display`, `__getitem__`→`Index`.
2. Lowering : une classe ayant `__add__(self, o) -> T` → `impl Add for C { type Output = T; fn add(...) {...} }`.
3. Inférence : `a + b` où `a` est un type ayant `__add__` → trait Add satisfaite, résultat = `T`.

## Critère de done
`Vec2 + Vec2`, `==`, `<`, `str(v)` via dunders → compile+run (fixtures) ; type sans `__add__` + `+` → erreur
claire ; non-régression opérateurs sur primitives. Corpus + binding VERTS.

## Notes
Séquentiel, dépend des traits (4.1, `impl`). Hors ensemble béni → non surchargeable (filet rustc).
