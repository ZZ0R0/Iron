# [23500] Surcharge d'opérateurs (`__dunder__` → `std::ops`)

- Version : V11 · Milestone : M11 · Statut : draft · Dépend de : 23400 · Invariants : I6, I2

## Objectif
Permettre la **surcharge d'opérateurs** sur les types utilisateur (chantier C) via des **méthodes spéciales**
(dunders), désucrées en `impl std::ops` Rust — `Vec(x=1) + Vec(x=2)` marche. Projection des traits d'opérateurs
Rust (I6), ensemble **béni** et fixe.

## Périmètre
Ensemble **béni** méthode → trait Rust :
`__add__`→`Add` · `__sub__`→`Sub` · `__mul__`→`Mul` · `__div__`→`Div` · `__eq__`→`PartialEq` ·
`__lt__`→`PartialOrd` · `__str__`→`Display` · `__getitem__`→`Index`.
- Une classe avec `__add__(self, o) -> T` → `impl Add for C { type Output = T; fn add(self, o) {…} }`.
- `a + b` sur type user → `a + b` Rust (résout via l'`impl`). Le moteur : `Trait(a, Add)` satisfaite par
  l'`impl`, résultat = type de retour du dunder.
- `__eq__`/`__lt__` → dérivation des comparaisons ; `__str__` → `Display` (utilisable en f-string/`print`).

## Hors-périmètre
- Dunders hors ensemble béni → non surchargeable (filet `rustc`). `__hash__`, `__iter__`… post-v0.

## Comportement attendu
```
class Vec2:
    x: i64
    y: i64
    def __add__(self, o) -> Vec2:
        return Vec2(x=self.x + o.x, y=self.y + o.y)
def main():
    v = Vec2(x=1, y=2) + Vec2(x=3, y=4)
    print(v.x)                       # 4
```

## Contrat / interface
`lower.rs` : un dunder reconnu dans une classe → `impl <Trait> for <Type>` (signature Rust attendue : `add`,
`Output`…). `infer/engine` : `a ⊕ b` sur un type ayant le dunder → contrainte de trait satisfaite, résultat
typé. `parse.rs` : `__add__` est un nom de méthode valide (déjà ident).

## Source maps
I8 : mauvais usage d'un opérateur surchargé → erreur `rustc`/native remontée sur la ligne Iron.

## Critères d'acceptation
- `Vec2 + Vec2`, `==`, `<`, `str(v)` via dunders → compile+run (fixtures). Type sans dunder + `+` → erreur
  claire. Non-régression des opérateurs sur primitives.

## Décomposition
→ planif : (1) table dunder→trait + désucrage `impl std::ops` ; (2) inférence (`a⊕b` user → résultat dunder).

## Risques / questions ouvertes
- 🔶 `Output` associé (type de retour de `__add__`) : pris du `-> T` du dunder (annoté ou inféré).
