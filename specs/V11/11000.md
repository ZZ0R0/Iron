# [11000] Patterns : or-patterns + range patterns

- Version : V11 · Milestone : M11 · Statut : draft · Dépend de : 20300 · Invariants : I2, I9

## Objectif
Compléter le `match` (chantier B) avec deux motifs manquants : **or-patterns** (`1 | 2 | 3`) et **range
patterns** (`0..10`, `0..=10`), désucrés vers les motifs Rust équivalents.

## Périmètre
- **or-patterns** (DB-1) : `p1 | p2 | …` dans un bras de `match`. Lexer accepte `|` en contexte motif ;
  parser → `Pattern::Or(Vec<Pattern>)` ; lowering → `p1 | p2` Rust. Bindings incohérents entre alternatives →
  erreur claire (règle Rust).
- **range patterns** (DB-2) : `lo..hi` **exclusif** · `lo..=hi` **inclusif** (entiers/chars). Parser →
  `Pattern::Range(lo, hi, inclusive)` ; lowering → `lo..hi` / `lo..=hi`.

## Hors-périmètre
- Vérif d'exhaustivité maison (DB-3 : `rustc` filet).

## Comportement attendu
```
match n:
    1 | 2 | 3:  return "petit"
    4..10:      return "moyen"     # 4..9
    10..=20:    return "grand"     # 10..20 inclus
    _:          return "autre"
```

## Contrat / interface
`ir.rs` : variantes `Pattern::Or` / `Pattern::Range`. `lex.rs` : `|` toléré (déjà `BitOr`). `parse.rs` :
parsing des motifs `|`/`..`/`..=`. `lower.rs` : émission des bras Rust.

## Source maps
I8 : chaque motif porte son `Span` (bras de `match` déjà tracés).

## Critères d'acceptation
- `1 | 2 | 3`, `0..10`, `0..=10` compilent + matchent correctement (fixtures).
- or-pattern avec binding incohérent → erreur claire.
- Non-régression du `match` existant (littéraux, variantes, gardes, imbriqués).

## Risques / questions ouvertes
