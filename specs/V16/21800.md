# [21800] Inférence whole-program : propagation inter-appels + annotation de retour respectée

- Version : V16
- Milestone : ownership-whole-program (frictions secondaires)
- Statut : draft
- Dépend de : [21700+] (moteur de contraintes I15), I11/I13 (Option/Result depuis le flux)
- Invariants applicables : I11, I12, I13, I15

## Objectif
Boucher trois trous de l'inférence révélés par le ray tracer, qui ont **forcé des annotations artificielles** :
(a) un **membre jamais appelé** laisse fuir un type libre `__T60` jusqu'à `rustc` ; (b) un **type concret ne se
propage pas** le long d'une chaîne d'appels (`HitRecord` à travers `ray_color → shade → shade_lambert`) ; (c)
une **annotation de retour explicite est ignorée** quand un `Option` est « deviné ». L'esprit : l'inférence est
whole-program pour les types — elle doit l'être **jusqu'au bout des arêtes d'appel** et **respecter** ce que
l'utilisateur a écrit.

## Périmètre
- **(a) Membre non appelé** : inférer depuis le **corps** (usage des champs/arith) ; à défaut, **diagnostiquer
  clairement** (« param non inférable, annote ») au lieu de laisser fuir `__T<n>` vers `rustc`.
- **(b) Propagation inter-appels** : un type d'argument **concret** connu chez l'appelant se propage dans la
  signature de l'appelé, **sur plusieurs niveaux** (point fixe sur le graphe d'appels — le même que [30500]).
- **(c) Annotation de retour prioritaire** : `def f() -> T:` impose `T` ; un fall-through possible **ne réécrit
  pas** silencieusement en `Option[T]` — soit on prouve l'exhaustivité du `return`, soit on **diagnostique**.

## Hors-périmètre
- L'inférence des **déclarations** de génériques (le 0.1 % HM-global). On infère params/retours, pas les `[T]`.
- L'inférence Option/Result **légitime** depuis le flux (I11) reste : seul le cas où elle **écrase une annotation
  explicite** (c) est corrigé.

## Comportement attendu

**(a) membre non appelé** — `Vec3.cross` n'est appelée nulle part → son param reste `__T60` :
```python
def cross(self, o) -> Vec3:        # AVANT : `o` non inférable → error: cannot find type __T60
    return Vec3(x=self.y*o.z - self.z*o.y, ...)
# APRÈS : inféré `o: Vec3` depuis l'usage (o.x/o.y/o.z + arith) ; sinon diagnostic clair "annote o".
```
**(b) propagation inter-appels** — `rec: HitRecord` connu chez `ray_color`, perdu dans `shade`/`shade_lambert` :
```python
def ray_color(scene, r, depth):
    rec = scene.world.hit(r, ...)   # rec : HitRecord (connu ici)
    return shade(rec, scene, r)     # AVANT : `rec` redevient __T48 dans shade → "no field point on __T48"
                                    # APRÈS : HitRecord propagé le long de l'arête d'appel (point fixe)
```
**(c) annotation de retour** — `-> Vec3` ignoré au profit d'`Option<Vec3>` :
```python
def random_in_unit_sphere() -> Vec3:   # AVANT : `return` conditionnel dans while True → -> Option<Vec3> (+None)
    while True:
        p = random_vec()
        if p.ok():
            return p
# APRÈS : l'annotation -> Vec3 est la VÉRITÉ ; `while True` sans break ⇒ pas de fall-through ⇒ pas d'Option.
```

## Contrat / interface
- **(b)** partage l'infrastructure **graphe d'appels + point fixe** de [30500] : types **et** modes circulent le
  long des mêmes arêtes (cohérence). Décision figée : une seule construction de graphe d'appels, consommée par
  l'inférence (b) et l'ownership ([30500]).
- **(c)** quand une annotation de retour existe, elle **prime** ; le moteur de flux (`infer/engine/flux.rs`)
  prouve l'exhaustivité (`while True` sans `break` ⇒ exhaustif) ou émet un **diagnostic** I8 (pas une réécriture).
- **(a)** repli d'inférence depuis le corps pour un membre sans site d'appel ; sinon diagnostic ciblé.

## Source maps

## Critères d'acceptation
- Le ray tracer compile **sans** les annotations `cross(self, o: Vec3)`, `rec: HitRecord`, `scene: Scene`,
  `r: Ray` qu'il a fallu ajouter (ou, pour (a), avec un **diagnostic clair** si le repli ne suffit pas).
- `random_in_unit_sphere() -> Vec3` reste `Vec3` (pas d'`Option` injecté).
- Corpus 80 reste vert (aucune inférence existante cassée).

## Risques / questions ouvertes
- **🔶 (a) repli depuis le corps** peut être ambigu (plusieurs types possibles) → préférer un **diagnostic** net
  à une devinette fragile. À trancher en planif.
- **❓ (c) preuve d'exhaustivité** : se limiter aux cas sûrs (`while True` sans `break`, `match` exhaustif,
  `if/else` couvrant) ; sinon diagnostic. Périmètre exact à figer en planif.
