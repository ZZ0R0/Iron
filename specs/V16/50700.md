# [50700] Résolution d'import `.iri` récursive (tous les modules, pas seulement l'entrée)

- Version : V16
- Milestone : ownership-whole-program (frictions secondaires)
- Statut : draft
- Dépend de : [50200] (`.iri` manuels), [50400] (deux couches), résolution d'import du driver
- Invariants applicables : I7, I7bis

## Objectif
Permettre à **n'importe quel module** Iron d'importer le **crate** dont il a besoin, là où il l'utilise. Aujourd'hui
la résolution « module `.irn` **ou** binding `.iri` » n'existe **qu'au fichier d'entrée** ; un `import mathx`
dans un sous-module échoue (`No such file: mathx.irn`). Le ray tracer a dû **remonter tous les imports de
bindings dans `main.irn`** — couplage artificiel qui casse le découpage en modules.

## Périmètre
- `load_module` (driver.rs) : pour chaque `import` d'un sous-module, appliquer la **même** résolution que la
  racine — registre curé embarqué (`import std`) → module `X.irn` → binding `X.gen.iri`/`X.iri` — récursivement.

## Hors-périmètre
- Le **modèle deux couches** lui-même ([50400]) — inchangé. On réutilise la résolution existante, on l'applique
  partout.

## Comportement attendu
**Cause racine [SOURCE]** : `driver.rs` `load_module` fait `for sub in &mod_ast.modules { load_module(sub, …) }`
→ **tout import d'un sous-module est supposé `.irn`**. La branche `.irn`-puis-`.iri` (résolution complète) ne
vit qu'au niveau de `compile()`.

**Attendu** : factoriser la résolution d'un import en **une** routine (curé → `.irn` → `.gen.iri`/`.iri`) et
l'appeler **et** à la racine **et** dans `load_module`. Les bindings d'un sous-module alimentent le même
`Bindings` global (les fns deviennent disponibles au programme fusionné).

```python
# objects.irn (sous-module)
import mathx                  # AVANT : échoue (cherche objects-dir/mathx.irn)
                             # APRÈS : résout mathx.gen.iri comme à la racine
def hit(...):
    return tan(theta)        # fn du binding mathx, disponible
```

## Contrat / interface
- **Entrée/sortie** : inchangées (l'AST fusionné + `Bindings`). Seul le **chemin de résolution** des imports de
  sous-modules change.
- **Décision figée** : un import non résolu en module **ET** non résolu en binding → erreur **claire** (comme à
  la racine : « ni module `X.irn`, ni binding `X.gen.iri`/`X.iri` ; lance `ironc add X` »).
- **Cycles & diamants** : la garde existante (`loaded`/`loading`) couvre les modules ; les bindings se fusionnent
  (idempotent par clé).
