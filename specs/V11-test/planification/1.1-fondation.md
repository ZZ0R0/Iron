# 1.1 — Fondation : harnais + datasets + contrat + `factor` e2e

> Vague 1, **séquentiel**. **Gèle** le contrat partagé (sinon les 30 pistes le combleraient différemment).
> Aucune modif `ironc/src`. Possède : `tests/v11-test/{bench.sh, gen_data.py, data/, factor/}`.

## Périmètre

1. **`gen_data.py`** — générateur **déterministe** des datasets (sans aléa non semé / horodatage) :
   - `data/text_big.txt` : ~2 M lignes synthétiques (mots pseudo-aléatoires **semés**, longueurs variées).
   - `data/text_sorted.txt` : `text_big` trié (pour `uniq`).
   - `data/bin_big.txt` : ~20 Mo d'octets ASCII variés (pour `od`/`cksum`/`histogram`).
   - `data/csv_big.txt` : ~1 M lignes `a,b,c,d` numériques (pour `cut`/`csvsum`).
   - `data/json_big.txt` : `[n1, n2, …]` (~1 M nombres) pour `jsonsum`.
   - `data/sorted_a.txt`, `data/sorted_b.txt` : listes triées (pour `comm`).
   - `data/words_big.txt`, `data/text_tabs.txt`, `data/nums_*.txt` selon besoins.
   - **Tailles réglées** pour **≥ 1 s côté CPython** sur le programme le plus rapide (amortit le startup).
   - Lancé **une fois** ; les datasets sont des **entrées figées** du bench.

2. **Contrat d'appariement & d'invocation** (cf. README §contrat) — **gelé** ici :
   - dossier `tests/v11-test/<prog>/` avec `<prog>.py` + `<prog>.irn`, même corps, zéro type.
   - invocation `<bin> <dataset|N>` → **une ligne** de résumé. Différences `.py`/`.irn` = entrée + imports.

3. **`bench.sh`** — le harnais différentiel + perf :
   - pour chaque `tests/v11-test/<prog>/` :
     - `ironc build --release <prog>.irn` → binaire `iron_out` ; **échec build = ligne ROUGE** (noté).
     - **correction** : `out_py = python3 <prog>.py <in>` ; `out_iron = <bin> <in>` ; **doivent être ==**.
     - **perf** (si correction OK) : N≥10 runs `taskset -c 0` de chaque, garde **min** (+ médiane) ;
       `speedup = t_py / t_iron`.
   - **vérifie 0 `unsafe`** dans le Rust généré (`grep -c unsafe` hors `forbid`).
   - imprime le **tableau** `prog · même_sortie · t_py · t_iron · speedup` + **moyenne géométrique** des speedups.
   - `hyperfine` utilisé s'il est présent, sinon fallback `taskset`+`date +%s.%N` (déjà prouvé en PoC).

4. **`factor/` e2e** — la 1ʳᵉ piste, **déjà prouvée** (PoC ~21×) : `factor.py` + `factor.irn` (corps identique)
   câblés dans `bench.sh` → **colonne verte** qui valide tout le harnais.

## Interface produite (consommée par 3.x/4.x)

- **Convention de dossier** + **invocation** + **format de sortie** (une ligne) + **datasets nommés**.
- `bench.sh` découvre automatiquement tout `tests/v11-test/<prog>/` conforme → **ajouter un programme =
  créer son dossier**, rien d'autre. (Découplage total → fan-out parallèle.)

## Definition of Done

- `gen_data.py` génère les datasets de façon déterministe (rejouable).
- `bench.sh` tourne, découvre `factor/`, confirme **même sortie** py3↔iron, imprime une ligne de speedup, et
  un tableau (même à 1 ligne) + moyenne géométrique.
- `factor.irn` : 0 `unsafe`, 0 annotation. **Colonne e2e verte**.
- Le contrat est **figé** (toute évolution = décision, pas un agent de fan-out qui le change).
