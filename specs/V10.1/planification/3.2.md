# [3.2] Display borné + defaulting final + retours génériques (generalize.rs)

- Spec parente : V10.1/R2 · Version : V10.1 · Dépend de : 2.1 · Statut : todo · **Vague 3** (parallèle)

## But
Trois raffinements de clôture (D-c/R2, D-j, D-l), tous dans `generalize.rs` :
- **R2** : un param **affichable seul** devient `T: Display` (générique **borné**) au lieu du défaut `str` →
  `label("x", 42)` marche (`42` est `Display`). Numérique → toujours `i64`.
- **D-j** : le defaulting est la **dernière** étape, après convergence du point fixe.
- **D-l** : un retour qui dépend d'un param générique est lui-même générique (réécriture).

## Fichiers touchés
`src/infer/engine/generalize.rs` (**possédé**). Lecture seule : `subst.rs`, `assume.rs`, `constraint.rs`.

## Étapes
1. **R2** : dans le defaulting, une var libre avec borne **`Display` seule** → générique implicite **portant
   la borne** `Display` (les bornes sont déjà collectées par `var_bounds`). Veiller à ce que le lowering émette
   `T: Clone + Display` (génériques bornés, piste 4.1 de V9.1).
2. **D-j** : s'assurer que `default_free_vars` ne tourne **qu'après** la boucle (l'ordre est garanti par
   `mod.rs`/1.1) — vérifier qu'aucun défaut n'est posé en cours de boucle.
3. **D-l** : `writeback` propage les génériques implicites des params vers le **retour** quand il en dépend.

## Critère de done
`label(prefix, n)` (f-string) compile et `label("x", 42)` marche **sans annotation** ; un défaut n'est jamais
posé avant convergence ; un retour générique est correctement déclaré ; corpus + binding + zero-annot VERTS.

## Notes
Parallèle à 3.1 (gen.rs disjoint). Garde-fou : **numérique → `i64`** reste prioritaire sur Display (sinon
`x + 1` casserait). Display→générique **uniquement** si la var n'a **que** la borne d'affichage.
