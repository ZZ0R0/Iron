# [2.1] Cœur : bascule monomorphe + promotion sur conflit

- Spec parente : V10.1/R1 · Version : V10.1 · Dépend de : 1.1 · Statut : todo · **Vague 2**

## But
Le changement central, **atomique** (D-a, D-b, cœur de D-g) : les appels unifient les args avec les **vrais**
params (monomorphe) ; un param **non annoté** qui reçoit deux types incompatibles est **promu générique** et
la boucle re-solve. `count(xs)` s'infère depuis l'appel ; `id` reste polymorphe **par promotion**.

## Fichiers touchés
`src/infer/engine/gen.rs` (logique d'appel : `instantiate`/`call`) · `src/infer/engine/promote.rs`
(`detect_conflicts` + `promote`) · `src/infer/engine/mod.rs` (la boucle itère réellement).

## Étapes
1. `gen.call` : un appel unifie `arg_i = param_i` du **vrai** callee. `instantiate` ne **freshise** que les
   génériques **déclarés** + les params dans `Promoted` (plus de freshise systématique).
2. `detect_conflicts` : pendant/après le solve, repérer les **params non annotés** qui unifieraient deux types
   **incompatibles** (concrets ≠). Param **annoté** en conflit → **erreur** (D-b, via `diag`).
3. `promote` : ajouter ces vars à `Promoted` ; les marquer génériques.
4. `mod.rs` : boucler `gen → solve → detect → promote` **jusqu'au point fixe** (plus de nouveau conflit).
5. Defaulting/writeback inchangés (vague 3 les raffine).

## Critère de done
`count([1,2,3])` (param non annoté) compile **sans annotation** (xs = list[i64] depuis l'appel) ; `id(7)` +
`id("hi")` ⇒ `id[T]` polymorphe ; conflit sur param **annoté** ⇒ erreur Iron nette ; **corpus 50 + binding 30
+ vitrine + zero-annot VERTS**. Point fixe prouvé terminant (test : pas de boucle infinie).

## Notes
**Séquentiel, atomique** : mono **et** promotion landent ensemble (mono seul casserait `id`). C'est le gate
interne de la vague 2 : ne pas clore tant que `id` **et** `count` ne passent pas tous les deux.
