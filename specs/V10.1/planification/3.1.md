# [3.1] Incrémental structurel + ordre supérieur (gen.rs)

- Spec parente : V10.1/R1 · Version : V10.1 · Dépend de : 2.1 · Statut : todo · **Vague 3** (parallèle)

## But
Exploiter la boucle (D-g **complet**) : à chaque tour, la `Subst` accumulée est réinjectée dans la
génération → les **usages structurels** d'un param (champ `x.name`, méthode `obj.m()`, index `xs[i]`) se
résolvent **une fois la base connue** (typiquement depuis le site d'appel). Plus D-h : un param **appelé**
comme fonction reçoit son type `fn(…) -> …` du site d'appel.

## Fichiers touchés
`src/infer/engine/gen.rs` (**possédé**). Lecture seule : `assume.rs`, `subst.rs`, `constraint.rs`.

## Étapes
1. **Field/Index/Method** : dans `gen.expr`, résoudre via `subst.apply(base)` — qui, au tour ≥ 2, voit la base
   déjà fixée (ex. `x = Point` venu de l'appel) → champ/méthode/élément typés ; sinon var fraîche (re-tenté au
   tour suivant). Le retour `return x.name` devient concret.
2. **HOF (D-h)** : un param `f` **appelé** (`f(x)`) → contrainte `f : fn(typeof(x)) -> fresh` ; au site
   d'appel `g(double, …)` le vrai `double` fixe `f`. Repli `fn(i64)->i64` si aucun appel concret.
3. Vérifier la convergence : la réinjection lie strictement plus → la boucle (2.1) termine.

## Critère de done
`def f(x): return x.name` + `f(Point(...))` ⇒ retour `str` **sans annotation** ; `def apply(g, v): return g(v)`
+ `apply(double, 5)` ⇒ typé ; corpus + binding + zero-annot VERTS.
