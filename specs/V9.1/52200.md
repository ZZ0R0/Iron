# [52200] `import std` : la bibliothèque standard Rust par import

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 52000, 52100 · Invariants : I5, I6, I7

## Objectif
Donner accès à la **std Rust** via le même mécanisme d'import que les crates — c'est le **remplaçant** des
pseudo-modules io/os/time retirés (52000). `import std` (ou `import std::collections`) rend `HashMap`, `fs`,
`env`, `thread`, `time`… disponibles, **sans aucune lib Iron**.

## Périmètre
- `import std` → charge un `.iri` **curé bénia** de `std` (fourni dans le registre, 52300) couvrant les
  modules courants : `std::fs` (read/write), `std::env`, `std::process`, `std::collections` (déjà partiellement
  natif via list/dict/set), `std::time`.
- `std` n'a **pas** de version ni de dépendance Cargo (intégré au toolchain) → cas spécial dans le résolveur :
  pas d'entrée `[dependencies]`, pas de rustdoc à tirer du réseau (rustdoc de std si dispo, sinon `.iri` curé).
- Namespacing : `std.fs.read_to_string(path)`, `std.env.var(name)` (namespacing 51500).

## Hors-périmètre
- Auto-binder **toute** la std (énorme) → on curte un sous-ensemble utile ; le reste via `rust { }`.

## Comportement attendu
```
import std
def main():
    content = std.fs.read_to_string("data.txt")?
    print(content)
```
→ `std::fs::read_to_string("data.txt")` + erreur → IronError.

## Contrat / interface
`driver` : `import std` → `.iri` curé `std` (registre). Le `.iri` `std` déclare les fns/types bénis avec
leurs chemins `std::…`. Pas d'injection de dépendance Cargo (std est implicite).

## Critères d'acceptation
- `import std` + `std.fs.read_to_string(p)?` compile + s'exécute (lecture d'un fichier réel).
- Aucun module io/os/time spécial dans le compilateur (cohérent 52000).
- `std` ne crée pas d'entrée `[dependencies]` fausse.
