# [60800] Diagnostics haute-fidélité par overlay rustc (la surcouche)

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 60100, 60900, 40100 · Invariants : I2, I8

## Objectif
Donner à Iron des **diagnostics de qualité production** sans écrire de type-checker maison (source de
faux-positifs, cf. le report de 5.2). Méthode = **la surcouche**, identique au codegen : on **transpile en
Rust**, on lance **`cargo check`**, et on **remonte les erreurs `rustc` en `Span` Iron** (I8). rustc fait le
travail dur (types, borrow, traits) ; Iron ne fait que mapper. Zéro faux-positif : si rustc accepte, c'est bon.

## Périmètre
- **`ironc check <fichier>`** : transpile → `cargo check` (pas de build complet) → parse la sortie `rustc`
  (JSON `--message-format=json`) → mappe chaque erreur (fichier/ligne/col Rust) vers le `Span` Iron via les
  source-maps (60900) → diagnostics Iron (fichier/ligne/col `.irn` + message **réécrit** en termes Iron quand
  possible).
- **Deux niveaux** (D4) : (1) erreurs **lex/parse/inférence locale** Iron = instantanées ; (2) erreurs
  **profondes** (types/traits) = via l'overlay rustc, plus lent.
- **Réécriture des messages** : best-effort — « `regex::Regex` n'a pas de méthode `is_matsh` » plutôt que le
  message rustc brut, quand le mapping le permet ; sinon message rustc + position Iron.

## Hors-périmètre
- Un solveur de types Iron complet (on délègue à rustc, D2).

## Comportement attendu
`r.is_matsh("a")` (typo) → `cargo check` échoue → remontée : `main.irn:5:7: méthode inconnue (rustc: no method
is_matsh)`, position **Iron** exacte.

## Contrat / interface
`driver::check` : transpile + `cargo check --message-format=json` + résolution Span. Consommé par `ironc check`
(CLI) et le LSP (71300). Dépend de source-maps fines (60900).

## Source maps (I8)
**Cœur de la spec.** La précision des diagnostics = la précision du mapping `Span` Iron ↔ ligne/col Rust
(60900). Chaque erreur rustc est résolue au `Span` Iron le plus fin couvrant la position.

## Critères d'acceptation
- Erreurs de type/méthode/borrow → diagnostic positionné sur le **bon `Span` Iron** (tests par catégorie).
- **Zéro faux-positif** (tout programme qui compile → 0 diagnostic).
- `cargo check` (pas build) → plus rapide que le build complet.

## Décomposition
→ planif `B1` : `ironc check`, parsing JSON rustc, mapping Span, réécriture best-effort, tests.

## Risques / questions ouvertes
- 🔶 Latence `cargo check` (secondes) → le LSP la lance en arrière-plan (D4) ; cache incrémental cargo aide.
- 🔶 Mapping multi-ligne / macro-expansion (idiomes, `format!`) → certaines erreurs tombent sur une ligne
  approximative ; documenter, raffiner via 60900.
