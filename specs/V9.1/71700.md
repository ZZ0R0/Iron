# [71700] Client LSP + linter dans VSCode (panneau Problems)

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 71500, 71300, 60800, 60500 · Invariants : I8

## Objectif
Brancher l'extension VSCode (71500) sur le serveur `ironc lsp` (71300) pour les **diagnostics, complétion,
hover live** dans l'éditeur, et faire apparaître les **lints** (`ironc lint`) + remontées rustc (60800) dans
le **panneau Problems**. C'est « l'orthographe/correcteur dans VSCode » demandé.

## Périmètre
- **Client LSP** : `vscode-languageclient` lance `ironc lsp` (stdio) et le connecte au langage `iron`.
  Diagnostics → soulignement + Problems ; complétion/hover/go-to-def câblés.
- **Lints dans Problems** : les diagnostics `IRN-Lxxx` (60500) et les erreurs overlay rustc (60800) remontent
  via le LSP dans Problems, avec sévérité (warn/error) et code cliquable.
- **Quick-fixes de base** : pour un lint « variable inutilisée » → action « préfixer `_` » / « supprimer ».
- Configuration : chemin du binaire `ironc`, activation de l'overlay (lourd) optionnelle.

## Hors-périmètre
- Le gestionnaire d'imports (71800) ; build/run (71900).

## Comportement attendu
Erreur de syntaxe → soulignée en rouge + dans Problems ; variable inutilisée → soulignée en jaune (IRN-L001) ;
`r.` propose les méthodes ; survol → type.

## Contrat / interface
`extensions/vscode/` : `vscode-languageclient`, lancement `ironc lsp`, mapping diagnostics→Problems. Dépend du
LSP enrichi (71300) et des lints (60500).

## Source maps (I8)
Les positions des diagnostics (LSP) reposent sur les `Span` Iron ↔ positions éditeur (I8/60900).

## Critères d'acceptation
- Diagnostics live (syntaxe + lint + overlay) dans l'éditeur et Problems, positionnés correctement.
- Complétion/hover fonctionnent dans VSCode (test manuel scripté + capture).
- Quick-fix d'un lint applicable.
