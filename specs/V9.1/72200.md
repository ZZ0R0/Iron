# [72200] `ironc doc` : génération de documentation

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 51800, 60900 · Invariants : I8

## Objectif
Donner à Iron une **doc-gen** (`ironc doc`). Comme le reste, **overlay sur l'outillage Rust** : on transpile
en Rust (avec les commentaires `#` → doc-comments `///`) et on lance **rustdoc**, puis on présente la doc
indexée par symbole Iron.

## Périmètre
- **Commentaires doc** : les commentaires `#` au-dessus d'une `def`/`class` deviennent des `///` Rust (doc-
  comments) → repris par rustdoc.
- **`ironc doc`** : émet le crate (via `ironc lib` 51800, items publics) + lance `cargo doc` → HTML rustdoc.
- **Signatures** : affichées en **types Iron** (mapping inverse) quand possible, sinon Rust.
- Ouverture du HTML généré.

## Hors-périmètre
- Un moteur de doc Iron natif (on réutilise rustdoc, D2).
- Doc-tests Iron (post-v0).

## Comportement attendu
```
# Additionne deux entiers.
def add(a: i64, b: i64) -> i64:
    return a + b
```
`ironc doc` → page rustdoc pour `add` avec « Additionne deux entiers. ».

## Contrat / interface
`lower` : commentaires `#` au-dessus d'un item → `#[doc = "…"]`/`///`. `driver::doc` : `ironc lib` + `cargo doc`.
Dépend de la préservation des commentaires (lexer trivia, cf. 71400).

## Source maps
N/A direct ; la doc référence les items (pas les lignes).

## Critères d'acceptation
- `ironc doc` génère une doc HTML avec les commentaires `#` repris.
- Signatures lisibles (types Iron de préférence).

## Décomposition
→ planif `D6` : commentaires `#`→`///`, `ironc doc` (lib + cargo doc), mapping signatures, test.

## Risques / questions ouvertes
- 🔶 Affichage des **types Iron** dans rustdoc (qui montre du Rust) → best-effort ; au minimum la doc-string
  est correcte. Mapping inverse type Rust→Iron optionnel.
