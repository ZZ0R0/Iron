# [71900] Build / run intégrés VSCode

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 71500, 70100 · Invariants : —

## Objectif
Compiler/exécuter un programme Iron **depuis VSCode** sans terminal : tasks `ironc build/run/test`,
**build-on-save** (diagnostics frais), exécution au clic (codelens/bouton), affichage des erreurs dans
Problems.

## Périmètre
- **Tasks** : `contributes.taskDefinitions` / `tasks.json` pour `ironc build`, `run`, `test`, `fmt`, `lib`.
- **Build-on-save** (optionnel/config) : à la sauvegarde, lance `ironc check` (60800) → diagnostics à jour.
- **CodeLens « ▶ Run »** au-dessus de `def main()` → exécute `ironc run` ; « ▶ Test » au-dessus des `def test_*`.
- **Terminal intégré** : sortie d'exécution dans un panneau ; erreurs cliquables (matcher → position Iron).
- Commandes palette : `Iron: Build`, `Iron: Run`, `Iron: Test`, `Iron: Format`.

## Hors-périmètre
- Le debug (72300) ; le LSP (71700).

## Comportement attendu
Cliquer « ▶ Run » sur `main` → exécute, sortie dans le terminal ; sauvegarder → diagnostics rafraîchis ; une
erreur de build est cliquable et saute à la **ligne Iron**.

## Contrat / interface
`extensions/vscode/` : task definitions, problem matchers (parse la sortie `ironc` → diagnostics positionnés),
codelens provider, commandes.

## Source maps (I8)
Le problem-matcher mappe les erreurs `ironc` (déjà en `Span` Iron) vers les positions éditeur.

## Critères d'acceptation
- Tasks build/run/test/fmt fonctionnent depuis VSCode.
- Build-on-save rafraîchit les diagnostics ; codelens « Run » exécute `main`.
- Une erreur est cliquable → ligne Iron correcte.

## Décomposition
→ planif `C5` : tasks, problem matcher, codelens, build-on-save, commandes.

## Risques / questions ouvertes
- 🔶 Build-on-save peut être lent (cargo) → débattu / `check` plutôt que `build` complet.
