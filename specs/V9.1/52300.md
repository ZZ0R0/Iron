# [52300] Registre de bindings curés + `ironc add` (la « stdlib de facto »)

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 50900, 52100 · Invariants : I7

## Objectif
Puisqu'Iron n'a **aucune lib** (D1), son « batteries included » = un **registre de `.iri` curés** des crates
Rust populaires (modèle @types/nimble). Ces crates bénis **sont** la stdlib de facto. `ironc add <crate>`
ajoute le crate + récupère son `.iri` curé. Finit 70800/2.5.

## Périmètre
- **Dossier `bindings/`** versionné : `bindings/<crate>/<version>.iri` (curé : auto-bind + retouches +
  instance-pinning + idiomes). Inclut le `.iri` curé de **`std`** (52200).
- **`ironc add <crate>`** : édite `ironc.toml` (`[dependencies]`) + place le `.iri` curé (ou auto-bind si absent).
- **Seed top-N** : l'équipe cœur curte serde_json, regex, rand, chrono, tokio, clap, anyhow, itertools, **std**…
- **Priorité de résolution** (52100) : `.iri` curé du registre > auto-bind caché.

## Hors-périmètre
- Hébergement réseau du registre (un dossier/dépôt suffit au v0).

## Comportement attendu
- `ironc add serde_json` → `serde_json = "1"` dans `ironc.toml` + `.iri` curé en place.
- `import serde_json` utilise le `.iri` curé (couverture > auto seul).

## Contrat / interface
`bind`/`driver` : résolveur de registre (`bindings/<crate>/<ver>.iri`) ; `ironc add` édite `ironc.toml`.
Le `.iri` curé est un `.iri` v2 (50900) — auto-bind **+ édité main**.

## Critères d'acceptation
- `ironc add regex` + `import regex` → compile+run via `.iri` registre.
- ≥ **8 crates bénis** curés (dont `std`), chacun ≥ 1 programme de test.
- Crate absent du registre → fallback auto-bind (52100), pas d'erreur.

## Décomposition
→ planif `A4` : structure `bindings/`, `ironc add`, résolveur, seed top-N + `std` + tests.

## Risques / questions ouvertes

- 🔶 Qualité des `.iri` curés = le vrai travail communautaire (cf. modèle @types).
