# [90600] Le « 0.1 % » tracé (hors-périmètre explicite)

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : — · Invariants : I2, I6, I7

## Objectif
**Documenter ce qu'on NE fait PAS**, explicitement, pour que ça ne soit ni oublié ni promis par erreur. Ce
sont les éléments structurellement coûteux ou de recherche, hors de l'ambition « langage utilisable » de V9.1.

## Périmètre (ce qui est tracé comme hors-périmètre)
- **Inférence Hindley-Milner complète** : Iron reste sur inférence **locale + dirigée par l'usage** (pas de
  solveur global d'unification). Conséquence : certaines annotations restent nécessaires.
- **Auto-hébergement** : le compilateur Iron **n'est pas** écrit en Iron (il reste en Rust). Pas de bootstrap.
- **Async exotique** : `select!`, pinning manuel, streams complexes, async-traits → `rust { }`.
- **Coroutines/`yield` complexes** : générateurs lazy/infinis, `yield from`, `send` → `rust { }`.
- **Binding GARANTI de n'importe quel crate** : les API à bornes de traits custom non-bénies, macros lourdes,
  lifetimes essentiels → `rust { }` ou `.iri` curé. Couverture auto mesurée 62–92 % (V8), pas 100 %.

## Hors-périmètre (de cette spec)
- Tout ce qui est dans une AUTRE spec V9.1 (c'est-à-dire : presque tout le reste). Cette spec ne liste **que**
  l'irréductible.

## Comportement attendu
Un dev qui rencontre un de ces cas obtient un **message clair** (« générateur trop complexe — utilise
`rust { }` », « borne de trait non bindable — fournis un `.iri` curé ») plutôt qu'un échec obscur.

## Contrat / interface
Documentation dans `generator.md`/`realisation.md` ; messages d'erreur des specs concernées (10900, 21200,
51600…) orientent vers `rust { }`/`.iri`. Aucune implémentation propre.
