# [72100] Gestion de paquets : `ironc.toml` + lockfile + résolution de versions

- Version : V9.1 · Milestone : M9.1 · Statut : draft · Dépend de : 70300, 52100, 52300 · Invariants : I7

## Objectif
Maturer la gestion des dépendances : aujourd'hui `ironc.toml` injecte les crates en brut. Ajouter un
**lockfile** (versions figées, builds reproductibles) et une **résolution de versions** sérieuse — la base
d'un écosystème (puisque tout passe par les crates, D1).

## Périmètre
- **`ironc.toml`** : `[dependencies] regex = "1"` (semver), `[iron]` (entry, runtime async D4).
- **Lockfile** : déléguer au **`Cargo.lock`** du projet généré (les crates étant des deps Cargo) → reproductible
  via cargo. Iron expose `ironc.lock` = miroir/lien du `Cargo.lock`.
- **`ironc add/remove/update`** : éditent `ironc.toml` + déclenchent la résolution (cargo) + invalident le
  cache de bindings (52100) si version change.
- **Résolution** : déléguée à cargo (semver, features) ; Iron ne réinvente pas un résolveur.

## Hors-périmètre
- Publication de paquets **Iron** (un module Iron se publie en crate via `ironc lib` 51800 + cargo publish).
- Registre réseau (52300 est local au v0).

## Comportement attendu
`ironc add regex@1.10` → `ironc.toml` + résolution cargo + lock figé ; build reproductible ; `ironc update`
met à jour dans les bornes semver.

## Contrat / interface
`driver` : `ironc.toml` → `[dependencies]` du projet généré (déjà), + exposition du `Cargo.lock` comme
`ironc.lock`. `ironc add/remove/update`. Invalidation du cache bindings sur changement de version.
