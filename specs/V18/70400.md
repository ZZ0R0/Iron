## Objectif
Matérialiser la **métrique de vérité** que le projet diffère depuis le début : un **corpus de programmes `.irn`
à sortie attendue**, exécuté automatiquement (compile + run + assert), re-joué **à chaque changement** du
compilateur. Donne la **confiance** (fini le spot-check manuel — on en a refondu l'ownership V16/V17 en
lançant 4-5 programmes à la main), **sécurise tout refactor** (corpus-gate réel), et **chiffre la correction**.

## Périmètre
- Un **dossier de cas** : chaque cas = un `.irn` + son **attendu** (stdout exact, OU « compile seulement »,
  OU « doit échouer avec tel diagnostic »).
- Un **runner** intégré à `cargo test` : pour chaque cas, `ironc run`/`build` → comparer à l'attendu.
- Un **rapport** : N passés / échoués, et **lesquels** (avec le diff de sortie).
- Le **seeding déterministe** des cas non-déterministes (RNG) pour des sorties stables.

## Hors-périmètre
- La **génération** des cas (c'est un travail de contenu continu). Ici on pose l'**infrastructure** + un
  premier lot.
- Le binding de crates lourds dans le CI (les cas à `ironc add` coûteux → lot séparé/optionnel).

## Comportement attendu
```
tests/corpus/
  arith.irn          arith.out          # stdout attendu exact
  closure_map.irn    closure_map.out
  raytracer/…        raytracer.sha       # image : hash attendu (RNG seedé)
  bad_type.irn       bad_type.err        # doit échouer ; diagnostic attendu (substring)
```
- **Cas « sortie »** : `ironc run cas.irn` → stdout == `cas.out` (exact). Sinon échec + **diff**.
- **Cas « compile »** : `ironc build cas.irn` réussit (pas de sortie à vérifier).
- **Cas « erreur »** : `ironc check/build` **échoue** ET le diagnostic contient `cas.err` (robustesse des messages).
- Intégré à `cargo test` (un `#[test]` par cas, ou un test paramétré) → **`cargo test` = corpus rejoué**.

## Contrat / interface
- **Format figé** : `<nom>.irn` + un fichier-attendu dont l'extension code le **type** (`.out`/`.compile`/`.err`/`.sha`).
- **Sortie** : code de sortie non-nul si un cas régresse + la liste des régressions (nom + diff).
- **Déterminisme** : les cas RNG fixent leur graine (binding `fastrand` seedé) → sortie reproductible.
- **Décision figée** : le corpus de cas vit **dans le dépôt** (`ironc/tests/corpus/`), versionné — c'est la
  garde de référence, pas un artefact jetable.

## Critères d'acceptation
- `cargo test` exécute le corpus (≥ un premier lot couvrant : arith/collections/match/struct/enum/closures/
  io-fichier/un crate simple/le raytracer) et **passe**.
- Une **régression introduite volontairement** (ex. casser un mode d'ownership) **fait échouer** `cargo test`
  avec le cas + le diff → preuve que la garde **mord**.
- Un **nombre chiffré** « N/N cas verts » est produit (la métrique de vérité).

## Risques / questions ouvertes
- **❓ Cas non-déterministes** (RNG, threads, hashmap order) : seeding + sortie triée. À border par cas.
- **❓ Coût CI des cas à `ironc add`** : lot « rapide » (sans crate lourd) par défaut, lot « complet » opt-in.
- **🔶 C'est l'axe le moins « excitant » mais le plus structurant** : il transforme « je crois que ça marche »
  en « je sais, mesuré ». Sans lui, V18 (closures/async/ergonomie) avancerait à l'aveugle.
