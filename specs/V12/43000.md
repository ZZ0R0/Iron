# [43000] Émission `no_std` + HAL encapsulé (embarqué)

- Version : V12
- Milestone : M12
- Statut : draft (cadrage)
- Dépend de : [40100] lowering core, [70200] driver cargo
- Invariants applicables : **I2 (jamais d'`unsafe` émis par Iron)**, I9, I10

## Objectif

Cibler l'**embarqué** : ESP32 (`esp-hal`), Raspberry Pi (`rppal`), capteurs I²C/SPI
(`linux-embedded-hal`), série (`serialport`), BLE (`btleplug`). Mur **dur** : Iron émet du **`std`** et ne
produit **jamais** d'`unsafe` (I2) — or l'embarqué exige `no_std` et l'accès matériel passe par de l'`unsafe`.

## Périmètre

- Un **mode d'émission `no_std`** : `#![no_std]` + `#![no_main]`, allocateur/`panic_handler` fournis,
  Cargo configuré pour la cible (`thumbv7em-…`, `xtensa-…`).
- Une **crate-HAL bénie** qui **encapsule** tout l'`unsafe` requis (GPIO, horloges, périphériques) derrière
  une API **sûre** : Iron appelle cette API sûre, ne génère jamais d'`unsafe` lui-même (I2 préservé).

## Hors-périmètre

- Async embarqué (`embassy`) en V12.
- Toolchains/targets non-Rust (bare-metal exotique).

## Comportement attendu (esquisse)

```
# Iron (forme cible — blink LED ESP32)
def main():
    p = Peripherals.take()          # API sûre de la crate-HAL bénie (unsafe encapsulé côté HAL)
    led = p.gpio2.into_output()
    loop:
        led.toggle()
        delay_ms(500)
```

## Critères d'acceptation (cible)

- Un blink LED compile pour une cible `no_std` (au moins **build vert** ; flash matériel = manuel).
- **Zéro `unsafe`** dans le Rust émis par Iron (I2) — l'`unsafe` vit dans la crate-HAL.
