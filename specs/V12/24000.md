# [24000] FONDATION V12 — Le pont de correspondance de types Iron↔Rust (refactor)

- Version : V12 · Milestone : M12 · Statut : **cadrage (fondation)** · Dépend de : — · Invariants : I2, I6, I9, I10
- **Rôle** : 1ʳᵉ vague de TOUTE la V12. Tout le reste (24100 et dérivés) se construit dessus.

## Pourquoi cette fondation existe (constat de dette)

Le stress-test des 80 a produit **B5→B33** : ~30 correctifs de binder. Le diagnostic du census
(`planification/README.md` §0) est sans appel — la **correspondance Iron↔Rust est encodée TROIS fois**,
sans source unique de vérité :

1. **Projection** (`bind.rs` : `map_type`/`map_named`/`map_prim`/`bound_to_iron`) — type Rust (rustdoc) → type Iron `.iri`.
2. **Inférence** (`infer/local.rs` : `builtin_method_ret`/`extern_iter_elem`, `infer/mod.rs : extern_method_ret`) — typer le résultat d'une méthode externe.
3. **Coercition** (`lower.rs` : `extern_arg_to`/`coerce_to`/`coerce_sized_binop`/`num_kind_str`/`try_*`) — valeur Iron → expr Rust à la frontière.

La **même** correspondance (ex. `Vec<u8>`/`&[u8]` ⟷ `list[u8]`) est codée en dur dans les 3. Ajouter un
motif de crate = toucher 1 à 3 endroits, **en oublier un** (c'est exactement comme B22/B29/B30 sont nés :
le type d'élément géré en projection mais pas en coercition/inférence). **Chaque crate-bug futur reproduit
ce schéma.** C'est de la dette structurelle, pas un manque de features.

## La grande solution (dont les petites dérivent)

Un **pont** = **source unique de vérité** de la correspondance Iron↔Rust, avec deux faces dérivées des
**mêmes données** :

- **Données partagées** (un seul jeu de tables, pilotées par la donnée et non par des `match` épars) :
  table numérique (`NumKind` ⟷ nom Rust ⟷ cast), table des conteneurs (`Vec/Option/Result/HashMap…`),
  table trait-borne→type (`AsRef<Path>`→`str`…), table octets (`list[u8]` ⟷ `&[u8]`/`Vec<u8>`).
- **Face projection** (consommée par `bind.rs`) : type rustdoc → `Type` Iron.
- **Face coercition** (consommée par `lower.rs`) : (`expr`, `Type` Iron, cible Rust) → `TokenStream`.
- **Face inférence** (consommée par `infer/`) : `Type` d'un résultat externe, **substitution de génériques** comprise.

> **Le levier** : suivre les **paramètres de type** (`T` dans `Foo<T>`). Aujourd'hui le binder écrase
> `Point<f64>` → `Extern("Point")` et **jette `f64`**. En le **gardant**, deux choses arrivent :
> 1. **[24100] génériques** devient l'expression directe de la fondation (geo/nalgebra/ndarray/polars/rustfft/ML…).
> 2. Le **problème des bornes de trait-crate disparaît** pour le cas dominant : `Point::new(x: T)` borné
>    `T: CoordNum` n'a **plus besoin** qu'on reconnaisse `CoordNum` — `T` **circule** et s'**instancie** par
>    le type de l'argument à l'appel (`Point.new(1.0, 2.0)` ⇒ `T=f64`). On **suit** au lieu de **whitelister**.
>    → moins de cas-par-cas **structurellement**, present et futur (l'objectif que tu as posé).

## Décision d'ABI — représentation des génériques externes (à figer en vague 1)

Le `Type` Iron (`ir.rs`, gelé) doit **porter les args** d'un type externe générique. Trois options :

| Option | Forme | Coût | Verdict |
|---|---|---|---|
| (a) étendre | `Type::Extern(String)` → `Type::Extern(String, Vec<Type>)` | casse **tous** les `match Type::Extern(_)` | plus pur, churn élevé |
| **(b) variante dédiée** ✅ | **`Type::ExternApp(String /*rust_path*/, Vec<Type>)`** | **additif** ; `Extern` opaque inchangé | **retenu** |
| (c) réutiliser `App` | `Type::App(name, args)` | `App` abaisse un **ident nu** (`name<args>`), pas un **chemin** (`crate::Point::<args>`) | inadapté |

**✅ Décidé : option (b)** — `Type::ExternApp(rust_path, args)`, **additive** donc non régressive. Lowering :
`rust_path::<args>` (réutilise la logique de chemin d'`Extern` + la logique d'args d'`App`, déjà présentes
en `lower_type`). `Vec` vide ⇒ équivalent `Extern`. Un nettoyage futur *pourra* fusionner `Extern` dans
`ExternApp` ; pas maintenant (stabilité d'abord).

**Schéma `.iri` (la donnée échangée — à figer aussi, I9)** : un type externe générique s'écrit `Point[f64]`
(le parser `.iri` lit déjà `[...]` pour `list[T]`/`Option[T]`). Le bloc `extern type` déclare ses **params** :
`extern type Point[T] = "geo::Point":` → l'`ExternType` mémorise `["T"]`, base de la **substitution** en inférence.

## Périmètre de la fondation (vague 1 squelette + vague 2 fan-out + vague 3 unif)

- **Module pont** : nouveau `src/bridge.rs` (nom de travail) — porte les **tables de données** + les 3 faces.
  `bind`/`infer`/`lower` y **délèguent** ; aucune ne ré-encode la correspondance.
- **`Type::ExternApp`** + lowering `path::<args>` + `.iri` `Name[args]` + `ExternType.params`.
- **Unifier le numérique** (R1) : un seul `cast_numeric(expr, from, to)` absorbe `coerce_to`,
  le volet numérique d'`extern_arg_to`, `coerce_sized_binop`. `num_kind_str` devient la table canonique.
- **Piloter par la donnée** (R3) : `bound_to_iron`/`map_named` consultent des tables (pas des `match` épars).
- **Substitution de génériques** (infer) : méthode de `Point[f64]` rendant `T` → `f64`.
