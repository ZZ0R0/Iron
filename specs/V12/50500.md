# [50500] Binder les constantes publiques d'un crate (`pub const`)

- Version : V12 · Milestone : M12 · Statut : draft (cadrage, **gap mineur**) · Dépend de : [50900] · Invariants : I6, I10

## Objectif
Référencer une **constante** exposée par un crate, quand c'est le point d'entrée de l'API : `base64`
s'utilise via `BASE64_STANDARD.encode(...)` où `BASE64_STANDARD` est un `pub const`. Iron ne binde
aujourd'hui que fns/méthodes/ctors/types — pas les constantes.

## Périmètre
- Le binder collecte les `inner.constant` publics → une nouvelle entrée `.iri` (`extern const NOM: T =
  "crate::chemin::NOM"`).
- infer type `NOM` (Var) en `Extern(T)` ; lower émet le chemin Rust complet.

## Hors-périmètre
- `static mut`, consts génériques.

## Questions ouvertes
- ❓ Syntaxe `.iri` : `extern const` (proche de `extern fn`).
- ❓ Collision nom de const vs nom de var locale.

## Done (cible)
`BASE64_STANDARD.encode("hello")` → base64 ; gate VERT. (Petit, mais débloque les API « moteur en const ».)
