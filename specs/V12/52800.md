# [52800] Modèle d'io par flux (`Write`/`Read`/`BufRead`)

- Version : V12
- Milestone : M12
- Statut : draft
- Dépend de : [50900] types externes à API, [40200] appels externes
- Invariants applicables : I2 (jamais d'`unsafe`), I4 (clone-fallback explicite), I6, I10

## Objectif

Permettre l'usage des crates d'**io par flux** — `flate2`, `image`, lecteurs/écrivains divers — dont l'API
repose sur `std::io::Write`/`Read`/`BufRead` : des **puits/sources d'octets** consommés en streaming, souvent
via des out-params `&mut Vec<u8>`. Aujourd'hui un mur dur : la sémantique **par valeur** d'Iron ne modélise
pas un puits mutable que l'on alimente progressivement.

## Périmètre

- Un **modèle d'octets en mémoire** : mapper `impl Write` / `impl Read` / `impl BufRead` (traits **std**) vers
  un tampon Iron `bytes` (≈ `list[u8]`), pour le cas dominant « (dé)compresser/transformer des octets en
  mémoire » : `e = GzEncoder.new(data, level)` ; `out = e.finish()` rend les octets.
- **Littéraux et coercitions d'octets** : un `bytes`/`list[u8]` Iron se construit depuis une chaîne
  (`s.encode()`), un littéral d'octets, ou une `list` d'entiers coercée en `u8`.
- **Tranches** : passer `&[u8]` (et non `&Vec<u8>`) là où un `R: BufRead`/`Read` l'exige.
- **Out-params** `&mut Vec<u8>` (ex. `read_to_end(&mut buf)`) : surface Iron par **valeur de retour** plutôt
  que mutation in-place (`buf = reader.read_to_end()`).

## Hors-périmètre

- Io **réelle** vers fichiers/réseau/stdout en streaming (rester en mémoire pour V12).
- Choix automatique de variante `read`/`write`/`bufread` au-delà du « tampon en mémoire » (à cadrer).
- `async` io.

## Comportement attendu

```
# Iron
data = "hello hello world world".encode()      # bytes
enc  = GzEncoder.new(data, Compression.best())  # tampon en mémoire
gz   = enc.finish()                             # bytes (compressés)
print(len(gz))

dec  = GzDecoder.new(gz)
back = dec.read_to_end()                         # bytes -> valeur de retour
print(back.decode())                             # "hello hello world world"
```

## Contrat / interface

- Un type Iron `bytes` (ou `list[u8]` typé) ↔ `Vec<u8>` Rust, avec coercition d'entrée depuis `str`.
- `bound_to_iron` : `Write`/`Read`/`BufRead` (std) → `bytes`. Convention **standard** (trait std), pas crate.
- Lowering : arg `bytes` vers `R: BufRead`/`Read` émis en **tranche** (`&data[..]`) ; out-param `&mut Vec`
  réécrit en valeur de retour.

## Source maps

Le lowering préserve les spans des appels ; les wrappers (`&data[..]`, retour d'out-param) héritent du span
de l'appel d'origine (I8).

## Critères d'acceptation

- `flate2` : compresser une chaîne puis la décompresser redonne la chaîne d'origine.
- `len(compressed) < len(original)` sur une entrée répétitive.
- gate-v11 reste VERT.

## Risques / questions ouvertes

- ❓ `bytes` comme **type propre** vs `list[u8]` spécialisé ? (impacte stdlib & inférence.)
- ❓ Out-param `&mut Vec` → valeur de retour : généralisable proprement, ou cas par cas io ?
- 🔶 `Write`→tampon suppose le cas **mémoire** : un `Write` réel (fichier) ne s'y mappe pas (hors-périmètre V12).
