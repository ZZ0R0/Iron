# [82000] Ergonomie des octets (`bytes`, itérateurs d'octets, hex)

- Version : V12 · Milestone : M12 · Statut : **partiel** (cadrage) · Dépend de : [24100], [52700] · Invariants : I6

## Objectif
Manipuler des **octets** confortablement : hacher et **afficher en hex**, clés binaires (sled), proof-of-work
(#80). Plusieurs briques manquent encore après B22/B26/B27.

## Périmètre
- ✅ **fait** : `str.encode()` → `list[u8]`, `bytes.decode()` → `str` (B27) ; coercition `list[u8]`/binop
  dimensionné (B22/B26).
- ❌ **manque** : **type d'élément d'un itérateur externe** — `for b in digest` doit donner `b: u8`. Le
  digest est un `GenericArray<u8, N>` dont l'`Item` (`u8`) vit dans la crate **étrangère `generic-array`** →
  non récupérable sans **binding multi-crate** ([52700]) ou suivi de génériques ([24100]).
- ❌ affichage **hex** d'un buffer (`{:02x}`) — découle de l'itération typée d'octets.

## Hors-périmètre
- Un type `bytes` distinct de `list[u8]` (à décider — `list[u8]` suffit peut-être).

## Questions ouvertes
- ❓ Récupérer l'`Item` d'un itérateur externe : via multi-crate (`generic-array`) ou via [24100] ?
- ❓ `bytes.hex()` builtin, ou laisser l'utilisateur boucler une fois l'élément typé ?

## Done (cible)
`Sha256.digest("x")` affiché en **hex** ; PoW (#80) trouve un nonce ; gate VERT.
