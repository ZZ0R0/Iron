# 24000.2 — VAGUE 2 piste A (`bind.rs`) : projection des génériques + tables pilotées-donnée

> Fan-out parallèle (avec 2.B, 2.C). **Ownership : `bind.rs`** (+ ses helpers de projection). Ne touche ni
> `lower.rs` ni `infer/` (ceux-là sont aux pistes B/C). Contrat amont gelé par `24000.1`.

## Dépendances amont
`24000.1` vert (interface `bridge`, `Type::ExternApp`, `ExternType.params`, schéma `.iri`).

## Périmètre exact

1. **Produire les args génériques** (le cœur de [24100]). Dans `map_named` (l.892-906) et `map_type`
   (l.853-890), la branche PascalCase ne renvoie plus le **nom nu** mais consulte les **params** du type :
   - Type externe générique `Point<f64>` → `Type::ExternApp("geo::Point", [F64])` au lieu de `Extern("Point")`.
   - Un **paramètre de type** `T` en position d'argument/retour de méthode → reste `Type::Generic("T")`
     (porté tel quel dans le `.iri` ; **plus jeté**). C'est ce qui débloque `new(x: T) -> Self` sans whitelist.
2. **Déclarer les params du type** : quand `project` traite un `impl`/struct générique, peupler
   `ExternType.params` (ex. `["T"]`) et émettre l'en-tête `.iri` `extern type Point[T] = "geo::Point":`.
3. **Bornes : suivre plutôt que whitelister** (réduction de dette). `bound_to_iron` (l.771-801) reste pour le
   cas « chaîne-like » (`AsRef<Path>`→`str`), mais devient une **table de données** (`bridge::BOUND_TO_IRON`),
   et le **fallback** d'un `T` non reconnu n'est plus « drop la fn » → c'est « garder `Generic("T")` », résolu à
   l'appel. (⇒ `Point::new`, `Series::new`, `query_row`/FromSql… cessent d'être droppés.)
4. **Migrer la projection vers `bridge::project`** : `bind.rs` **délègue** ; les tables `CONTAINERS`/`map_prim`/
   `bound_to_iron` vivent désormais comme **données** dans `bridge.rs`, consommées ici. (R3.)

## Fichiers possédés
- **Édition exclusive** : `src/bind.rs` (`map_type`, `map_named`, `map_prim` réduit à un appel-table, `project`,
  `bound_to_iron` → consulte `bridge`).
- **Lecture seule** : `src/bridge.rs` (tables + signatures gelées par 24000.1), `src/ir.rs`.
- **N'édite pas** `lower.rs`/`infer/` (pistes B/C) → pas de collision.

## Interface produite / consommée
- **Produit** : des `.iri` où les types externes génériques sont `Name[args]`, les params déclarés `Name[T]`,
  et les `T` de méthodes **préservés**. C'est l'entrée que 2.C (infer) substitue et 2.B (lower) monomorphise.
- **Consomme** : `bridge::{project, BOUND_TO_IRON, CONTAINERS}`, `Type::ExternApp`, `ExternType.params` (24000.1).

## Definition of Done (vérifiable)
1. `ironc add geo` régénéré : `extern type Point[T] = "geo::Point":`, `Point.new(x: T, y: T) -> Point[T]`,
   `euclidean_distance(self, other: Point[T]) -> T` (params **présents**, plus de drop).
2. `ironc add nalgebra`/`ndarray` : les ctors scalaires-génériques **apparaissent** (non droppés).
3. Tables de correspondance : **une** définition (dans `bridge`) — `grep` ne trouve plus de `match name { "Vec" => … }` dupliqué dans `bind.rs`.
4. Gate VERT (les `.iri` commités du gate ne sont pas régénérés). Diff `.iri` d'un crate non générique = vide.
