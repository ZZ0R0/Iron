# [50300] Auto-génération de bindings via `rustdoc --output-format json`

- Version : V2 · Milestone : M4 · Statut : draft · Dépend de : 50200 · Invariants : I7, I6

## Objectif
Niveau 3 (I7) : générer des `.iri` (50200) **automatiquement** à partir du JSON de `rustdoc`.

## Périmètre
Commande `ironc bind <crate>` : lance `rustdoc --output-format json`, parse le JSON, émet un `.iri`
(signatures publiques mappables vers le sous-ensemble de types Iron).

## Hors-périmètre
Items non mappables (génériques complexes, traits, lifetimes) → **ignorés avec rapport**, pas d'échec.

## Comportement attendu (observable)
- `ironc bind <crate>` → fichier `.iri` listant les `extern fn`/`extern type` publics dont la signature se
  **projette** vers le sous-ensemble Iron (I6) ; le reste est sauté et **listé** (pas de binding faux).
- Le `.iri` produit est consommable tel quel par 50200 (`use`).

## Contrat / interface
Entrée : sortie JSON de `rustdoc` (format nightly). Sortie : `.iri` au format 50200. Réutilise le mapping
type Rust↔Iron de 50200.

## Source maps
N/A (outil de génération).

## Critères d'acceptation
`ironc bind` sur une petite crate/`std` → `.iri` valide, importable (50200), appel qui compile ; items non
mappables listés, jamais bindés à tort.

## Décomposition
→ `planification/` (vague 4).

## Risques / questions ouvertes
- 🔶 **Format rustdoc-json instable** (nightly, versionné) : cibler une version, dégrader proprement sinon.
- 🔶 **Couverture de mapping** : volontairement **partielle** (sous-ensemble I6) ; honnêteté sur ce qui est sauté.
