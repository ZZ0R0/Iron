# [50100] Blocs `rust:` inline

- Version : V2 · Milestone : M4 · Statut : draft · Dépend de : 40100 · Invariants : I7, I2, I10, I8

## Objectif
Échappatoire bas niveau (I7 niveau 1) : émettre du **Rust verbatim** dans une fn Iron.

## Périmètre
Bloc `rust { … }` : le contenu est capté **brut** par le lexer (jamais tokenisé en Iron) et émis verbatim.
Les variables Iron en portée sont accessibles par leur nom Rust.

## Hors-périmètre
`rust:` en position expression (V2 = instruction). Forme indentée `rust:` (brace-only en V2).

## Comportement attendu (observable)
- `rust { let r = x.sqrt(); print!("{}", r); }` dans une fn → le texte est inséré tel quel à sa place.
- Var Iron `x` (même `&T` issu de V1) lisible par son nom.
- **Garde-fou I2** : `#![forbid(unsafe_code)]` en tête de crate ⇒ un `unsafe` dans le bloc **ne compile pas**.

## Contrat / interface
Lexer : `TokenKind::RustVerbatim(String)` (capté à brace-depth). AST : `StmtKind::RustBlock(String)`.
Lowering : le texte est parsé en `TokenStream` (`syn`/`proc_macro2`, **pas** de concat — I10) et inséré ;
invalide → erreur remontée (I8).

## Source maps
Le `rust:` porte un span ; une erreur `rustc` dans le bloc remonte (best-effort) au span du bloc.

## Critères d'acceptation
Une fn Iron avec `rust { … }` appelant du Rust réel → `cargo` vert + exécution correcte. `unsafe` rejeté.

## Décomposition
→ `planification/` (vague 2).

## Risques / questions ouvertes
- ❓ Pont de types : l'auteur doit connaître les types/emprunts générés (bas niveau, documenté).
